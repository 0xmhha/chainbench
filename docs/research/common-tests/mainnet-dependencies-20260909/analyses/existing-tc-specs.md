# 기존 TC 스펙과 ID 대응

263개 원본 항목을 유지하면서 기존 명세 ID를 우선 표기했다. 원문에 기록된 참조 196개는 Confluence에서 ID 존재를 확인했다. 참조가 없던 26개는 실행 단계와 명세를 대조해 부분 대응으로 연결했다. 41개는 명세 ID를 확정하지 않고 실행 ID를 표시한다.

## 표기 원칙

- `TC-1-1-01`, `RT-A-2-01` 등 기존 명세 ID를 그대로 사용한다. 축약 표현은 실제 ID가 원본 표에 모두 있을 때만 펼쳤다.
- 하나의 실행 테스트에 여러 명세가 연결되면 모두 표시한다. 같은 ID가 여러 원본 항목에 반복될 수 있다.
- `RPC-01`(WEMIX3.0)과 `RPC-001`(WEMIX4.0)은 다르다. 체인별 명세 URL을 함께 보존한다.
- JSON `catalog_id`와 family의 `source_ids`는 내부 연결 키다. 기존 분석 별칭을 유지하고 `display_id`, `original_spec_ids`, `spec_sources`를 추가했다.
- ID 연결은 구현 동등성·실행 성공을 보증하지 않는다. 기존 분류·우선순위·추가 제안 N-번호를 유지했다.
- `부분 대응`은 명세의 시나리오 중 확인된 부분이 연결된다는 뜻이다. 전체 판정까지 대신할 수 없다.

## 재검토 방법

`existing-id-crosswalk.json`에 원문 참조 표현, 기존 분석 키, 실행 ID, 명세 URL, 부분 대응 이유를 보존했다. 최신 코드로 분석을 재생성할 때 실행 ID와 source_file을 다시 대조한 뒤 표기 필드를 적용한다. 분석 순번만으로 새 결과에 연결하지 않는다. 원문 명세가 바뀌면 해당 페이지를 다시 읽어야 한다.

기존 문서는 `../id-revision-baseline/`에 보관했다. 소스 스냅샷과 실제 테스트 JSON은 수정하지 않았다.
