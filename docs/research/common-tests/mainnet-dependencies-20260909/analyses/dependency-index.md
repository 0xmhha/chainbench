# 공통 후보의 원본 의존 필드 색인

> ID 표기는 Confluence 원래 명세 ID를 우선한다. 실행 ID는 별도 표기한다. ID 대응은 전체 명세 충족이나 PASS를 뜻하지 않는다. [ID 대응표](existing-tc-specs.md)

문서 명세는 실행 시 필요한 의존 요소를 기록했고 JSON은 실제 key와 step 문맥으로 위치를 추적했다. 아래 수는 공통 JSON 92개 중 해당 필드가 직접 등장하는 파일 수다. 한 테스트에 여러 종류의 의존이 있으므로 합산하지 않는다. 빈 목록은 의존이 없다는 뜻이 아니다. 환경 상속·기본값은 별도 하네스 분석을 따른다.

literal은 원문에 고정된 값 또는 연산/메서드 선택이라는 뜻이다. 모든 literal이 잘못된 하드코딩은 아니다. 계정 역할(role), 실행 결과 binding, 설정 파일 참조(config-reference)를 구분했고 실제 값은 재출력하지 않았다.

| 구분 | 공통 JSON 직접 참조 파일 수 |
|---|---:|
| 테스트 계정 | 92 |
| RPC와 노드 선택 | 91 |
| 컨트랙트 | 12 |
| 체인 선택·Chain ID | 92 |
| 포크·genesis | 8 |
| 수수료·gas | 51 |
| 토폴로지·시간 | 92 |
| 바이너리·실행환경 | 92 |
