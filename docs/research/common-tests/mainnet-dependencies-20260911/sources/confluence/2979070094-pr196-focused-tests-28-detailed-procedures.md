## 문서 안내

WEMIX3.0 체인 중단 취약점 수정이 기존 기능에 미치는 영향을 확인한다. 총 28개이며 P0 3개, P1 20개, P2 4개, P3 1개다. 기존 테스트 20개와 신규 테스트 8개로 구성한다. 각 테스트와 세부 조건별로 실행 결과를 기록한다.

기존 명세 ID는 유지한다. 같은 기능의 명세와 자동 테스트는 하나의 항목으로 정리한다. 임시 분석 번호는 공식 테스트 ID가 아니다. [테스트 용어집](https://wemade.atlassian.net/wiki/spaces/platfomDev/pages/2978185459/PR196)을 함께 참고한다. 트랜잭션 영수증(receipt)은 블록에 포함된 트랜잭션의 실행 결과를 담은 정보다.

## 트랜잭션 유형별 확인 범위

지원 유형은 Legacy 트랜잭션 0x0, Access List 트랜잭션 0x1, 동적 수수료 트랜잭션 0x2, 수수료 대납 트랜잭션(FeeDelegateDynamicFee) 0x16이다. 각 유형의 정상 처리를 해당 트랜잭션 항목에서 확인한다. 컨트랙트 배포, 상태 변경, 이벤트 항목도 네 유형을 각각 실행한다. 28개는 문서의 항목 수이며 유형별 실행 결과는 따로 남긴다.

대상 WEMIX3.0에서 해당 트랜잭션 유형과 수수료 규칙이 활성화된 환경을 사용한다. 다른 체인의 설정값을 그대로 적용하지 않는다. 유형 미지원 설정이나 확인 자료 부족으로 실행할 수 없으면 판정을 보류하고 사유를 기록한다.

## 공통 준비 사항

1. 운영망과 분리된 WEMIX3.0 테스트망을 사용한다. 노드 버전, 제네시스 설정, 적용된 체인 규칙, 노드별 역할과 RPC 주소를 기록한다.
2. 계정은 테스트별로 구분한다. 잔액을 비교할 계정에는 다른 트랜잭션이나 블록 보상이 섞이지 않도록 한다. 비밀키와 인증정보는 결과 문서에 남기지 않는다.
3. 블록 크기와 메시지 크기는 구분해서 측정한다. 이 문서의 기준값은 검토한 PR196 패치인 5a9355 기준이다. 실행할 버전의 제한값이나 비교 조건이 달라졌다면 기대값을 다시 확인한다.
4. 블록 수신 상한은 8,388,608바이트(8 MiB), 메시지 수신 상한은 10,485,760바이트(10 MiB)다. 블록에 트랜잭션을 추가할 때 사용하는 별도 기준값은 7,388,608바이트다.
5. 노드 간 비교는 같은 블록 높이 H를 기준으로 한다. 각 노드의 최신 블록을 따로 조회해 비교하면 서로 다른 블록을 비교할 수 있다.
6. 수정 전후 비교에는 같은 체인 설정과 입력 자료를 사용한다. 크기 제한 때문에 트랜잭션이 나뉘어 담길 수 있으므로, 버전이 다른 노드가 각각 만든 블록의 해시가 항상 같아야 하는 것은 아니다.
7. 장애나 잘못된 블록을 다루는 테스트는 항목마다 별도 데이터 사본으로 시작한다. 계정과 노드 데이터를 공유하는 테스트는 동시에 실행하지 않는다.
8. 정확한 크기나 처리 경로를 확인할 수 없는 환경에서는 해당 항목을 통과로 기록하지 않는다. 필요한 측정값과 실행 기록을 확보한 뒤 판정한다.

## 결과 기록과 판정

각 테스트와 세부 조건별로 테스트 ID, 노드 버전, 환경 설정, 입력 자료, 기대값, 실제 결과, 판정, 근거 자료의 위치를 남긴다. RPC 응답, 트랜잭션과 블록의 해시, 트랜잭션 영수증, 계정 상태, 관련 로그를 함께 보관한다. 크기 테스트는 노드가 계산한 값과 실제 인코딩한 바이트 수를 각각 남긴다.

1. 통과: 모든 필수 조건을 실행했고 기대 결과가 일치한다.
2. 실패: 실행 결과가 기대 결과와 다르다. 입력 오류와 환경 문제를 구분해 기록한다.
3. 판정 보류: 환경, 처리 경로 또는 적용 정책을 확인할 수 없어 결론을 내릴 수 없다.
4. 미실행: 아직 실행하지 않았다. 일부 조건만 실행했다면 남은 조건을 명시한다.

기존 자동 테스트가 확인하는 범위와 이 문서에서 요구하는 확인 사항은 다를 수 있다. 아래의 ‘판정 시 유의 사항’을 함께 적용한다. 크기 제한을 초과한 블록 거부를 확인했더라도 정상 체인이 갈라지거나 동기화가 중단되면 배포 검증을 통과한 것으로 처리하지 않는다.

## RT-A-2-04 / TX-010 · 계정별 트랜잭션 순서 확인

우선순위: P0.

**준비:** 블록 생성을 제어할 수 있는 테스트망과 자금이 있는 송신 계정 2개를 준비한다. 트랜잭션 풀에 모든 트랜잭션을 보관할 수 있어야 한다.

1. 각 계정의 시작 nonce를 기록한다. 연속된 nonce의 트랜잭션을 순서대로 제출하는 경우와 역순으로 제출하는 경우를 나누어 실행한다.
2. 역순 제출은 모든 트랜잭션이 트랜잭션 풀에 도착한 것을 확인한 뒤 블록 생성을 재개한다.
3. 트랜잭션 영수증과 블록의 트랜잭션 목록을 수집한다. 같은 계정의 트랜잭션을 블록 번호와 블록 내 순서로 정렬해 nonce와 대조한다.

**기대 결과:** 각 계정의 트랜잭션이 nonce 순서대로 정규 체인에 한 번씩 포함된다. 서로 다른 계정 사이에는 하나의 공통 순서를 요구하지 않는다.

**판정 시 유의 사항:** 최종 nonce 값만으로 트랜잭션의 실제 포함 순서까지 확인했다고 판단하지 않는다.

기존 명세: RT-A-2-04 (2599813145) / TX-010 (2636711400)

## RT-A-1-02 / NODE-003 · 전체 동기화 확인

우선순위: P0.

**준비:** 정상 블록으로 구성한 기준 체인과 데이터가 없는 신규 노드를 준비한다. 비교할 높이 H의 블록 해시와 stateRoot를 저장한다.

1. 신규 노드를 full 모드로 기준 노드에 연결한다.
2. 전체 동기화로 블록을 받아 검증하고 저장하는지 로그에서 확인한다.
3. 높이 H에서 두 노드의 블록 해시와 stateRoot를 비교한다. 이어지는 블록도 정상 수신하는지 확인한다.

**기대 결과:** 전체 동기화가 실제로 수행되고, 같은 높이의 블록과 상태가 일치한다. 후속 블록도 계속 반영된다.

**판정 시 유의 사항:** 정상 체인을 대상으로 하며 같은 높이의 블록과 상태를 비교한다.

기존 명세: RT-A-1-02 (2599813145) / NODE-003 (2636711400)

## RT-A-1-06 · 누락된 블록의 일괄 동기화 확인

우선순위: P0.

**준비:** 연결을 끊었다가 복원할 노드와 Downloader의 요청·수신·저장 기록을 확인할 수 있는 환경을 준비한다.

1. 대상 노드를 격리하고 기준 노드에서 여러 블록을 생성한다.
2. 다시 연결한 뒤 Downloader가 누락된 블록을 요청하고 저장하는지 확인한다.
3. 같은 높이 H의 블록 해시와 stateRoot를 비교하고 후속 블록 수신을 확인한다.

**기대 결과:** Downloader로 누락된 블록을 받아 기준 노드와 같은 상태에 도달한다.

**판정 시 유의 사항:** 블록 높이에 차이가 있었다는 사실만으로 Downloader를 거쳤다고 판단하지 않는다. 처리 경로를 확인하지 못하면 판정을 보류한다.

기존 명세: RT-A-1-06 (2599813145)

## wemix-node-crash · 노드 중단 후 블록 생성과 복구 확인

우선순위: P1. 기존 명세 ID 미확인.

**준비:** 블록 생성 노드 7대를 준비한다. 중단 대상은 node3, 확인 대상은 node1로 정한다.

1. 블록 높이가 3 이상인 상태에서 node3를 중단한다.
2. node1의 블록 높이가 증가하는지 확인하고 node3를 다시 기동한다.
3. 복구한 node3와 기준 노드에서 같은 높이 H의 블록 해시와 stateRoot를 비교한다. node3가 후속 블록도 받는지 확인한다.

**기대 결과:** 한 노드가 중단되어도 다른 노드가 블록을 생성한다. 복구한 노드는 기준 노드와 같은 상태에 도달하고 후속 블록을 반영한다.

**판정 시 유의 사항:** 기존 자동 테스트는 재시작 후 동기화까지 검사하지 않는다. 복구 결과는 3번의 증거로 따로 확인해야 한다.

## RT-A-2-02 · 동적 수수료 트랜잭션 확인

우선순위: P1.

**준비:** 이 항목에서 type 0x2의 전송·블록 포함·정상 실행과 동적 수수료 처리를 함께 검증한다. 동적 수수료 트랜잭션이 허용된 WEMIX3.0 설정과 송신 계정의 자금을 준비한다. 송신자와 수신자의 잔액 및 송신 계정의 nonce를 기록하고, 다른 트랜잭션이나 보상이 잔액 측정에 섞이지 않도록 한다.

1. 대상 체인의 기본 수수료와 허용 규칙에 맞춰 type=0x2 트랜잭션을 서명하고 전송한다.
2. 트랜잭션 영수증, eth\_getTransactionByHash 응답, 해당 블록의 기본 수수료를 수집한다.
3. 같은 트랜잭션 해시를 기준으로 블록 포함, status=1, type=0x2와 송신 계정의 nonce 증가를 확인한다. 수신자 잔액 증가량과 송신자의 전송액·수수료 차감액을 비교하고, effectiveGasPrice가 해당 블록의 수수료 규칙과 일치하는지 확인한다.

**기대 결과:** status=1, type=0x2이며 수신자 잔액은 전송액만큼 증가한다. effectiveGasPrice는 해당 블록에 적용된 WEMIX3.0 수수료 규칙과 일치한다.

**판정 시 유의 사항:** 기존 자동 테스트는 status와 type만 확인한다. StableNet의 고정 팁이나 istanbul\_getWbftExtraInfo 응답을 WEMIX3.0의 기대값으로 사용하지 않는다.

기존 명세: RT-A-2-02 (2599813145)

## RT-A-2-06 · 잔액이 부족한 트랜잭션의 거부 확인

우선순위: P1.

**준비:** 다른 트랜잭션과 보상을 받지 않는 계정을 사용한다. nonce, 서명, 가스와 수수료는 유효하게 설정한다.

1. 송신자 잔액과 nonce를 기록하고 잔액보다 큰 금액을 전송하는 트랜잭션을 만든다.
2. 트랜잭션을 제출하고 반환된 오류가 잔액 부족인지 확인한다.
3. 블록이 정상 생성되는 동안 해당 트랜잭션의 미포함 여부를 확인한다. 송신자 잔액과 nonce, 트랜잭션 풀도 다시 조회한다.

**기대 결과:** 잔액 부족으로 거부된다. 트랜잭션이 정규 체인이나 트랜잭션 풀에 포함되지 않으며 송신자 잔액과 nonce가 바뀌지 않는다.

**판정 시 유의 사항:** 서명 오류나 RPC 연결 실패로 제출하지 못한 결과는 통과가 아니다. 기존 자동 테스트의 제출 거부 결과만으로 오류 원인까지 확인한 것은 아니다.

기존 명세: RT-A-2-06 (2599813145)

## RT-A-3-01 / TX-005 · 트랜잭션 유형별 컨트랙트 배포와 반환값 확인

우선순위: P1.

**준비:** 정수 42를 반환하는 동일 컨트랙트와 배포 자금을 준비한다. type 0x0, 0x1, 0x2, 0x16을 각각 별도 계정 또는 초기 상태에서 실행한다.

1. 수신 주소를 지정하지 않은 생성 트랜잭션에 배포 코드를 넣고 유형별로 서명·전송한다. type 0x16은 대납자 서명도 포함한다.
2. 각 트랜잭션의 type과 영수증 status=1을 확인한다. contractAddress가 유효한지 확인하고 그 주소의 eth\_getCode를 예상 런타임 코드와 비교한다.
3. 배포된 컨트랙트에 입력 데이터가 없는 eth\_call을 실행하고 32바이트 정수 42를 반환하는지 확인한다.
4. 송신 계정의 nonce 증가와 비용 부담을 확인한다. 대납 유형은 송신자와 대납자의 잔액을 구분한다.

**기대 결과:** 네 유형 모두 배포에 성공하고 각 주소에 예상한 코드가 존재한다. 조회 결과는 42이며 트랜잭션 유형, nonce와 수수료 처리가 일치한다.

**판정 시 유의 사항:** 배포 코드는 실행 코드와 다를 수 있으므로 eth\_getCode는 예상 런타임 코드와 비교한다. 상수 반환값 조회와 저장값 변경은 구분한다. 저장값 변경은 별도의 상태 변경 테스트에서 확인한다. 기존 배포 명세를 유형별로 반복하며 결과를 각각 남긴다.

기존 명세: RT-A-3-01 원본 (2599256076) / TX-005 원본 (2639659344)

## RT-A-3-06 · revert된 트랜잭션의 실패 결과 확인

우선순위: P1.

**준비:** REVERT를 실행하는 기존 테스트 컨트랙트와 유효한 트랜잭션을 준비한다.

1. 컨트랙트를 배포하고 배포 영수증의 status=1을 확인한다.
2. 컨트랙트에 트랜잭션을 보내 revert를 발생시킨다.
3. 트랜잭션이 블록에 포함되었는지와 해당 영수증의 status를 확인한다.

## 신규 테스트 N-008 · 미포함 트랜잭션의 이월과 교체 확인

우선순위: P1.

**준비:** 여러 계정의 연속 nonce 트랜잭션을 준비한다. 잔액, 가스, 수수료와 트랜잭션 풀 용량을 충분히 확보한다. 다른 트랜잭션의 유입이나 보관 정책 때문에 트랜잭션이 삭제되지 않게 한다.

1. 첫 블록이 크기 제한에 도달하도록 트랜잭션을 제출하고 해시와 nonce를 기록한다.
2. 새 블록을 반영한 트랜잭션 풀에서 미포함 트랜잭션을 확인한다. 같은 nonce의 트랜잭션을 교체할 때는 수수료 인상 조건을 충족하고 교체 수락을 확인한다.
3. 교체가 수락된 뒤 새 블록 생성 작업을 시작한다. 생성자를 바꾼 경우에는 새 생성자가 트랜잭션을 받았는지 확인한다. 후속 블록의 트랜잭션 순서와 영수증을 대조한다.

**기대 결과:** 크기 제한만을 이유로 유효 트랜잭션이 트랜잭션 풀에서 삭제되지 않는다. 후속 블록에 계정별 nonce 순서로 한 번씩 포함된다. 교체한 nonce에는 새 트랜잭션만 포함된다. 같은 블록을 반영한 노드의 상태와 영수증이 일치한다.

**판정 시 유의 사항:** 미포함 상태에서는 영수증이 없어야 한다. 앞선 큰 트랜잭션 때문에 블록에 여유가 남는 것은 검토한 패치의 트랜잭션 추가 종료 방식에 따른 결과일 수 있다. 수정 전후에 트랜잭션이 블록에 포함되는 순서와 구성가 같을 필요는 없다.

## 신규 테스트 N-009 · 거부된 트랜잭션과 실행 실패 트랜잭션의 상태 확인

우선순위: P1.

**준비:** nonce 오류, 잔액 부족, 블록 가스 부족, 허용되지 않은 트랜잭션 유형을 각각 준비한다. 별도로 블록에 포함 가능한 REVERT 트랜잭션과 가스 소진 트랜잭션을 준비한다.

1. 크기 검사에 통과하는 무효 트랜잭션과 크기를 초과하는 무효 트랜잭션을 구분한다. 각 트랜잭션 뒤에는 작은 정상 트랜잭션을 둔다.
2. 처리 전후의 계정 상태, nonce, 포함 트랜잭션 수, 누적 크기, 영수증과 가스 사용 내역을 기록한다.
3. 정상 트랜잭션, REVERT 트랜잭션과 가스 소진 트랜잭션도 각각 실행한다. 수정 전후의 오류별 처리 결과를 비교한다.

**판정 시 유의 사항:** 모든 내부 가스 집계가 일괄 복원된다고 가정하지 않는다. 오류별 기존 규칙과 비교한다. 크기 초과로 먼저 종료된 경우에는 뒤의 크기가 작은 트랜잭션이 반드시 포함되어야 하는 것은 아니다. 내부 처리 표시만으로 블록 포함을 판단하지 않는다.

## 신규 테스트 N-010 · 블록 생성 작업 변경 후 크기와 상태 확인

**판정 시 유의 사항:** 복사한 영수증의 내부 로그를 직접 변경하는 등 정상 트랜잭션 처리와 다른 조작까지 독립성을 요구하지 않는다. 트랜잭션의 후속 블록 포함은 N-008의 트랜잭션 풀 보관 조건에서 확인한다.

## 신규 테스트 N-011 · 트랜잭션 유형과 디코딩 방식별 블록 크기 확인

1. 같은 트랜잭션을 직접 생성·서명한 경우, 바이너리 인코딩 후 디코딩한 경우, RLP 인코딩 후 디코딩한 경우를 비교한다. 트랜잭션 해시가 같은지 확인한다.
2. 크기가 작은 typed 트랜잭션을 다수 넣은 블록과 트랜잭션별 허용 크기에 가까운 트랜잭션을 넣은 블록을 각각 생성한다.
3. 트랜잭션과 블록의 계산 크기를 기록하고, 완성 블록을 별도로 인코딩한 실제 크기와 비교한다.

**기대 결과:** 같은 트랜잭션은 디코딩 방식에 관계없이 같은 해시와 실행 결과를 유지한다. 완성 블록의 RLP 크기는 8 MiB 이하이다.

**판정 시 유의 사항:** 트랜잭션 자체의 계산 크기와 블록에 RLP 인코딩된 트랜잭션의 크기가 항상 같지는 않다. 차이를 실제 바이트 수로 기록하고 1,000,000바이트의 여유가 충분한지 확인한다.

## 신규 테스트 N-012 · 여러 블록 본문 응답의 크기 확인

우선순위: P1.

**준비:** 응답에 누적한 본문 크기가 2 MiB 바로 아래인 상태와, 이어서 추가할 8 MiB 이하 정상 블록의 본문을 준비한다.

1. 해당 블록들을 한 요청으로 조회한다.
2. ETH65의 본문 목록과 ETH66/68의 요청 식별자를 포함한 응답을 각각 인코딩한다. 메시지 전체 RLP 크기를 측정한다.
3. 수신 노드의 응답 수락을 확인한다. 한 응답에서 빠진 블록은 다시 요청해 모두 받는지 확인한다.

**기대 결과:** 정상 응답이 10 MiB를 넘지 않으며 요청한 모든 블록 본문을 받을 수 있다.

**판정 시 유의 사항:** 본문 합계만으로는 10 MiB 미만이어도 목록과 요청 식별자에 필요한 바이트가 추가된다. 이 테스트는 그 여유를 확인한다. 상한 초과가 이미 발생했다고 가정하지 않는다.

## 신규 테스트 N-013 · 대량 로그 영수증과 스냅 동기화 확인

우선순위: P1.

**준비:** 허용된 블록 가스 안에서 이벤트 로그를 많이 남기는 트랜잭션을 준비한다. 완성 블록은 8 MiB 이하여야 한다.

1. 한 블록의 영수증 묶음이 큰 경우와, 응답 누적 크기가 2 MiB 바로 아래에서 다음 묶음을 추가하는 경우를 각각 만든다.
2. GetReceipts로 조회하고 영수증 응답의 실제 RLP 크기를 측정한다.
3. 같은 자료로 수정 전후 노드의 수신과 스냅 동기화를 비교한다. 10 MiB에 도달할 수 없다면 체인 가스 한도에서 가능한 최대량과 근거를 기록한다.

**기대 결과:** 정상 체인의 영수증을 받아 동기화가 완료된다. 메시지 크기 제한으로 연결 해제와 같은 요청의 재시도만 반복되지 않는다.

**판정 시 유의 사항:** 블록이 8 MiB 이하라는 사실만으로 영수증 응답도 작다고 판단하지 않는다. 반대로 가스 규칙을 위반한 자료로 상한 초과를 만든 결과를 정상 체인의 결함으로 기록하지 않는다.

## 신규 테스트 N-014 · 크기 제한을 초과한 블록 거부 후 정상 블록 처리 확인

우선순위: P1.

**준비:** 크기 외의 헤더와 본문 조건이 유효한 크기 제한을 초과한 블록을 준비한다. 같은 정상 부모에서 이어지는 정상 대체 블록과 후속 블록도 준비한다.

1. 블록 전체 전달, 해시 공지 후 본문 요청, 누락 블록 일괄 동기화 경로로 크기 제한을 초과한 블록을 각각 전달한다.
2. 각 경로를 별도 상태에서 실행한다. 크기 제한을 초과한 블록 거부 후 정상 상대 노드가 정상 대체 블록과 후속 블록을 전달하게 한다.
3. 정규 체인의 블록, 계정 잔액과 영수증을 확인한다. 기준 높이 H의 블록 해시와 stateRoot를 정상 노드와 비교한다.

**기대 결과:** 크기 제한을 초과한 블록은 정규 체인에 반영되지 않는다. 정상 대체 블록으로 진행하고 노드 간 상태가 일치한다.

**판정 시 유의 사항:** 거부된 블록 때문에 잔액이 바뀌거나 그 블록이 정식 트랜잭션 영수증의 근거가 되어서는 안 된다. 정상 대체 블록은 거부된 블록의 자식이 아니라 정상 부모에서 이어져야 한다.

## 신규 테스트 N-015 · 블록 생성 종료 조건 확인

우선순위: P1.

**준비:** 트랜잭션 사전 처리 기능을 끈 경우와 켠 경우를 나누어 확인한다. 각 방식에 실제 적용되는 종료 조건을 기록한다.

1. 가스 한도 도달, 크기 한도 도달, 블록 생성 종료 조건 충족, 트랜잭션 수 상한 도달을 각각 먼저 발생시키는 입력을 준비한다.
2. 어떤 조건으로 트랜잭션 추가가 끝났는지 확인한다. 블록 생성 종료 조건은 최소 처리 트랜잭션 수 등 함께 요구되는 조건도 충족시킨다.
3. 완성 블록의 유효성과 적용 한도를 확인한다. 수정 전후 노드의 기존 종료 규칙도 비교한다.

**기대 결과:** 각 조건에서 트랜잭션 추가를 정상 종료하고 유효한 블록을 만든다. 크기가 먼저 한도에 도달하면 가스가 남아도 종료할 수 있다.

**판정 시 유의 사항:** 적용되지 않는 트랜잭션 수 제한을 새 요구 사항으로 추가하지 않는다. 모든 종료 조건의 검사 순서가 같다고 가정하지 않는다. 실행 기록에는 실제로 작동한 조건을 남긴다.

## RT-A-2-01 / TX-006 · Legacy 트랜잭션 전송과 실행 확인

우선순위: P1.

**준비:** 자금이 있는 송신자와 별도 수신자를 준비한다. nonce와 두 계정의 잔액을 기록한다. 대상 체인에서 허용되는 gasPrice를 사용한다.

1. gasPrice를 지정한 type=0x0 트랜잭션을 서명하고 전송한다. 트랜잭션 해시를 기록한다.
2. 다른 노드에서 같은 트랜잭션의 블록 포함을 확인한다. eth\_getTransactionByHash와 eth\_getTransactionReceipt를 조회한다.
3. type, status, nonce와 잔액 변화를 대조한다. 실제 가스 가격과 gasUsed로 수수료를 계산한다.

**기대 결과:** type=0x0, status=1이다. 송신 계정의 nonce는 1 증가하며 수신자 잔액은 전송액만큼 증가한다. effectiveGasPrice=gasPrice이고 송신자 잔액은 전송액과 가스 비용만큼 감소한다.

**판정 시 유의 사항:** 다른 트랜잭션이나 보상이 잔액 측정에 섞이지 않도록 한다. 같은 트랜잭션 해시를 기준으로 노드별 결과를 비교한다.

## RT-A-2-03 / TX-007 · Access List 트랜잭션 전송과 실행 확인

우선순위: P1.

**준비:** Access List 트랜잭션이 허용된 체인 설정을 사용한다. 송신 계정과 실제 접근할 주소와 스토리지 키가 있는 컨트랙트를 준비한다.

1. eth\_createAccessList 또는 확인된 주소와 스토리지 키로 비어 있지 않은 Access List를 준비한다. Access List 비용과 실행에 필요한 가스를 포함해 gasLimit을 정한다.
2. type=0x1과 Access List를 명시해 트랜잭션을 서명하고 전송한다.
3. 트랜잭션 조회 응답의 type과 accessList, 영수증의 status, 컨트랙트 실행 결과와 송신 계정의 nonce를 대조한다.

**기대 결과:** type=0x1, status=1이다. Access List가 제출한 내용과 같고 컨트랙트 실행 결과가 예상값과 일치한다. 포함된 트랜잭션에 맞게 nonce와 가스 비용이 반영된다.

**판정 시 유의 사항:** 빈 Access List를 사용한 기존 자동 테스트만으로 주소와 스토리지 키 처리를 검증했다고 판단하지 않는다. Access List에는 자체 가스 비용이 있어 전체 가스가 항상 더 적다고 요구하지 않는다.

기존 명세: RT-A-2-03 원본 (2599256076) / TX-007 원본 (2639659344)

## RT-A-3-02 · 트랜잭션 유형별 컨트랙트 상태 변경 확인

우선순위: P1.

**준비:** 값을 저장하는 함수와 조회하는 함수가 있는 컨트랙트를 준비한다. type 0x0, 0x1, 0x2, 0x16이 허용된 설정에서 각각 별도 초기 상태로 실행한다.

1. 컨트랙트의 초기 저장값과 송신 계정의 nonce, 송신자 및 대납자의 잔액을 기록한다.
2. 같은 상태 변경 함수를 네 유형의 트랜잭션으로 각각 호출한다. type 0x1에는 실제 Access List를 넣고 type 0x16에는 송신자와 대납자 서명을 모두 포함한다.
3. 각 트랜잭션이 포함된 블록에서 영수증과 type을 확인한다. eth\_call로 저장값을 조회하고 다른 노드의 같은 블록 기준 결과와 비교한다.
4. 송신 계정의 nonce와 수수료 차감을 대조한다. 대납 트랜잭션은 송신자와 대납자의 부담을 구분한다.

**기대 결과:** 네 유형 모두 status=1이며 저장값이 지정한 값으로 바뀐다. type과 nonce가 정확하고 동일 블록을 처리한 노드의 조회 결과가 일치한다. 비용은 각 유형과 대상 체인의 규칙에 맞게 반영된다.

**판정 시 유의 사항:** 상태 변경은 실제 서명 트랜잭션으로 실행한다. eth\_call 성공만으로 상태가 저장됐다고 판단하지 않는다. 기존 명세의 상태 변경 시나리오를 네 트랜잭션 유형으로 반복하며 세부 실행 결과를 각각 남긴다.

기존 명세: RT-A-3-02 원본 (2599256076)

## RT-A-4-04 / RPC-014 · 컨트랙트 실행과 이벤트 로그 확인

우선순위: P1.

**준비:** 정해진 이벤트와 값을 기록하는 컨트랙트를 준비한다. type 0x0, 0x1, 0x2, 0x16별로 실행 결과를 구분한다.

1. 이벤트를 발생시키는 함수를 각 유형의 서명 트랜잭션으로 호출한다. 블록 포함과 status=1을 확인한다.
2. 트랜잭션 영수증의 로그에서 컨트랙트 주소, topics, data와 트랜잭션 해시를 기대한 이벤트 및 값과 비교한다.
3. 해당 블록 범위와 컨트랙트 주소, topics를 지정해 eth\_getLogs를 조회한다. 영수증 로그와 대조하고 불일치하는 주소·토픽 조건에서는 해당 로그가 반환되지 않는지 확인한다.

**기대 결과:** 각 유형의 성공 트랜잭션이 예상한 이벤트를 남긴다. 영수증과 eth\_getLogs가 같은 로그를 가리키며 조회 조건에 맞는 결과만 반환한다.

**판정 시 유의 사항:** 빈 배열 또는 logs.count가 0 이상이라는 검사만으로 통과 처리하지 않는다. 기존 자동 테스트의 topic0 검사에 더해 이벤트 값과 조건별 조회 결과를 확인한다.

기존 명세: RT-A-4-04 원본 (2599256076) / RPC-014 원본 (2639659344)
