# 메인넷별 의존 요소

공통 테스트 76개가 기대는 메인넷 값을 다섯 가지로 나눠 적는다. 각 항목마다 "테스트에 어떻게 들어 있는지"와 "세 체인이 어디서 갈리는지"를 같이 적었다. 어느 테스트가 어느 항목에 기대는지는 상세 실행 절차 페이지의 "의존 요소"에 있다.

## 1. 테스트 계정

**테스트에 어떻게 들어 있나.** 계정은 세 가지 모양으로 나온다. 노드 역할 이름(예: 1번 노드), 고정된 주소, 테스트 중에 새로 만든 계정이다. 자동 테스트 195개 중 35개에 고정 주소가 적혀 있다. 대부분은 첫 번째 노드의 계정 주소이고, 나머지는 받는 용도로 정해 둔 주소다.

**세 체인이 갈리는 곳.**

- 노드가 갖고 있는 계정으로 서명하는 방식은 우리가 띄운 네트워크에서만 된다. 운영망 공개 RPC에는 잠금 해제된 계정이 없다.
- StableNet은 계정에 차단(blacklist)과 인증(authorized) 상태가 있다. 차단된 계정은 보내는 쪽이든 받는 쪽이든 수수료 대납자든 거부된다. 인증된 계정은 수수료 계산이 달라진다. 다른 두 체인에는 이 상태가 없다.
- 공통 테스트의 계정은 차단되지 않고 인증되지 않은 일반 계정이어야 한다.

## 2. RPC 주소와 API

**테스트에 어떻게 들어 있나.** 테스트는 주소를 직접 적지 않고 노드 역할 이름(생성 노드 1번, 종단 노드 1번)으로 대상을 고른다. 실행 도구가 역할 이름을 주소로 바꾼다. 우리가 띄운 네트워크에서는 역할이 자동으로 정해지지만, 외부 주소에 붙일 때는 모든 주소가 종단 노드로 취급되고 웹소켓 주소와 지표 주소가 없다.

**세 체인이 갈리는 곳.**

- 합의 정보 조회 API(검증자 목록, 서명자 목록, 합의 상태)는 WEMIX4.0과 StableNet에만 있다. WEMIX3.0은 관리 API와 거버넌스 컨트랙트 조회로 같은 정보를 얻는다. 자동 테스트 31개가 이 API를 부른다.
- Brioche 보상 조회 API는 WEMIX3.0과 WEMIX4.0에 있고, 제네시스에 Brioche 설정이 있을 때만 열린다. StableNet에는 없다.
- 세 체인 모두 기본으로 열어 두는 API 묶음은 net과 web3뿐이다. eth, txpool, admin 같은 나머지는 노드 실행 옵션으로 열어야 한다. 운영망 공개 RPC에서는 관리용(admin), 풀 조회(txpool), 개인 서명(personal)이 닫혀 있을 수 있다.
- 실행 도구의 WEMIX3.0 설정 파일에 적힌 검증자 조회 API 이름은 실제 노드에 없는 이름이다. 도구 자체는 다른 경로로 검증자를 읽으므로 설정 파일만 고치면 된다.

## 3. 컨트랙트 주소

**테스트에 어떻게 들어 있나.** 두 종류가 있다. 일반 컨트랙트는 테스트가 직접 배포하고 그 주소를 다음 단계로 넘긴다. 시스템 컨트랙트는 주소가 고정돼 있어 테스트에 직접 적혀 있다. 자동 테스트 62개가 StableNet 시스템 컨트랙트 주소(0x1000부터 0x1004까지)를 직접 부른다.

**세 체인이 갈리는 곳.**

- 일반 컨트랙트 배포와 호출은 세 체인 공통이다. 단, 배포할 코드가 세 체인의 EVM에서 모두 실행돼야 한다. WEMIX3.0은 최신 명령어(PUSH0)를 기본으로 켜지 않아, 최신 컴파일러로 만든 코드가 실행되지 않는다. 자동 테스트 하나(조회 호출 되돌림)가 이 명령어를 쓴다.
- 시스템 컨트랙트는 체인마다 다르다. WEMIX3.0은 고정 주소가 없고 레지스트리 컨트랙트에서 이름으로 주소를 찾는다. WEMIX4.0은 거버넌스 컨트랙트 4개(설정, 스테이킹, 보상, NCP)가 0x1000부터 0x1003에 있다. StableNet은 시스템 컨트랙트 5개(코인 어댑터, 검증자, 발행 관리, 발행, 위원회)가 0x1000부터 0x1004에 있다. 주소가 겹쳐도 함수와 뜻이 다르므로 주소만 바꿔 같은 테스트로 쓸 수 없다.
- P256 서명 검증 프리컴파일(0x100)은 WEMIX3.0에 없다.

## 4. 체인 ID

**테스트에 어떻게 들어 있나.** 자동 테스트 9개가 체인 ID를 확인하지만 모두 "0보다 큰가"만 본다. 설정값과 비교하는 테스트는 없다.

**세 체인이 갈리는 곳.**

- 노드 프로그램의 기본값은 WEMIX3.0과 WEMIX4.0이 같은 1111이고 StableNet은 8282다. 실행 도구가 사설망에 쓰는 기본값은 8285, 8284, 8283이다.
- 체인 ID만으로 WEMIX3.0과 WEMIX4.0을 구분할 수 없다. 체인 종류는 설정에 따로 적고, 합의 API 이름으로 확인한다.
- 공통 테스트는 "체인 ID가 설정값과 같다"로 검사해야 한다.

## 5. 그 밖의 설정과 실행 환경

**하드포크.** 자동 테스트 26개가 제네시스 값이나 하드포크 높이를 바꾼다. 항목 이름이 체인마다 다르다(StableNet은 boho와 anzeon, WEMIX는 brioche, 공통은 applepie). 계정 코드 위임(EIP-7702)은 WEMIX4.0이 블록 높이로, StableNet이 설정 존재 여부로 켠다. 두 체인 사이에서도 켜는 방법이 다르다.

**수수료.** 자동 테스트 12개가 StableNet 블록 헤더에만 있는 팁 값을 읽어(읽기 24회) 수수료 입력을 만든다. 기본 수수료 변화 규칙이 세 체인 모두 다르다. WEMIX3.0은 거버넌스 값, WEMIX4.0은 표준 계산(상한 없음), StableNet은 사용률 기준 계산(하한 20,000 Gwei, 상한 있음)이다. 최소 수수료 검사도 다르다. StableNet은 최대 수수료 하한(최소 기본 수수료와 최소 팁의 합)을 풀에서 검사하지만, WEMIX3.0과 WEMIX4.0의 풀은 팁 하한만 검사한다. 거부 사유 문구는 앞부분이 같고 뒤에 붙는 설명이 다르다.

**노드 구성과 시간.** 생성·전달·종단 노드 수, 기다리는 블록 수, 제한 시간이 테스트 안에 상수로 적혀 있다. 블록 주기가 다르면 이 값이 모두 어긋난다. WEMIX4.0과 StableNet은 1초, WEMIX3.0은 거버넌스가 정한다.

**노드 직접 제어.** 자동 테스트 17개가 노드를 멈추고 띄우고 연결을 끊는다. 우리가 띄운 노드에서만 된다. 운영망에서는 할 수 없다.

**노드 프로그램.** 테스트에 프로그램 이름이 적혀 있다. WEMIX4.0 프로그램의 실제 파일 이름은 WEMIX3.0과 같은 gwemix라서, 실행 도구 설정과 테스트 8개가 쓰는 이름(gwbft)과 다르다. 파일 이름으로 체인을 구분하면 안 된다.

**거부 판정.** 실행 도구의 "거부되어야 한다" 검사는 어떤 오류든 통과시킨다. 이유가 틀린 거부도 통과다. 공통 테스트는 거부 사유의 앞부분 문구까지 확인해야 한다.
