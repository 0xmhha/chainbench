# 별도 구현이 필요한 항목

값을 바꿔도 같은 입력에서 나와야 할 정답이 체인마다 다르거나, 실행 도구에 필요한 기능이 없는 항목이다. 두 부류로 나눈다. "체인별 정답 계산"은 공통 절차를 두고 정답만 체인별로 구하는 것이고, "도구 기능 추가"는 실행 도구에 없는 경로를 만드는 것이다.

## 1. 체인별 정답 계산이 필요한 것

| 항목 | 세 체인이 같이 쓰는 부분 | 체인별로 다른 부분 | 해당 테스트 |
|---|---|---|---|
| 수수료 규칙 | 트랜잭션, 영수증, 블록 헤더를 읽어 금액을 비교하는 절차 | 기본 수수료 변화식과 상한·하한, 최소 팁과 최소 수수료 기준, 실제 적용 가스 가격(StableNet 일반 계정은 헤더 팁으로 바뀜), 대납자 잔액 검사 기준 | CT-FEE-001~006, CT-FEE-010, CT-FEE-011, CT-TX-002, CT-TX-003, CT-TX-005, CT-TX-008 |
| 수수료 입력 출처 | 기본 수수료에 팁을 더해 최대 수수료를 만드는 절차 | 팁을 어디서 읽는지. StableNet은 블록 헤더, WEMIX3.0은 거버넌스 제안값, WEMIX4.0은 최근 블록 표본 | 헤더 팁을 읽는 자동 테스트 12개 |
| 거부 사유 판정 | 거부됐는지 확인하는 절차 | 사유 문구 뒤에 붙는 설명. 앞부분 문구로 판정하고 체인별 문구 표를 둔다 | CT-TX-006~008, CT-TX-015, CT-TX-016, CT-FEE-001, CT-FEE-002 |
| 합의 정상·장애 판정 | 블록 진행, 같은 높이 해시 일치, 피어 수 관찰 | 검증자 조회 방법, 허용되는 장애 수(WBFT는 3분의 2 이상 생존, WEMIX3.0은 etcd 과반), 블록 주기, 에폭 | CT-NODE-001, CT-NODE-011, CT-NODE-016, CT-FAULT-001~006 |
| 컨트랙트 코드 | 배포와 호출 절차 | 코드가 요구하는 EVM 버전. WEMIX3.0은 최신 명령어를 켜지 않는다 | CT-CONTRACT-001~003, CT-CONTRACT-005 |
| 계정 준비 | 계정 생성, 자금 지급, nonce 분리 | StableNet에서 차단·인증 상태가 아닌지 미리 확인 | 계정을 쓰는 모든 테스트 |
| 제네시스 준비 | 환경 선언 | WEMIX3.0은 노드 프로그램이 거버넌스 설정에서 제네시스를 만들고, 나머지는 템플릿에 값을 채운다. 기대 제네시스 해시는 체인별 | CT-NODE-003 |
| 동기화 관찰 | 동기화 상태, 높이 따라잡기 | 기본 동기화 방식(WEMIX3.0은 snap, 나머지는 full), WEMIX3.0의 생성 노드 간 동기화 점검 개입 | CT-NODE-004~007 |

## 2. 실행 도구에 추가해야 하는 것

| 기능 | 지금 상태 | 필요한 것 | 해당 테스트 |
|---|---|---|---|
| 로컬 서명 전송 | 자금 지급, 컨트랙트 배포, 등록 호출, 부하 전송이 모두 노드 서명이다. 로컬 서명 전송은 계약 생성이 안 되고 가스가 21000으로 고정된다 | 모든 전송이 로컬 키로도 되게 한다. 계약 생성, 데이터, 가스, nonce, 수수료, 접근 목록, 대납 형식을 한 경로에서 다룬다 | 공개 RPC에서 돌릴 모든 전송 테스트 |
| 기능 사전 확인 | 체인별 기능 지원표가 없다. 실행 도구 설정은 세 체인의 지원 형식을 같게 적어 두었다 | 계정 코드 위임, P256, 대납 형식, 합의 API, 계정 상태 기능을 실제 노드에서 확인하고, 없으면 "건너뜀"과 이유를 남긴다 | 형식·API 의존 테스트 전부 |
| 외부 주소 프로필 | 외부 주소는 역할이 없고 웹소켓·지표 주소가 없다 | 주소별 역할, 웹소켓·지표 주소, 인증 정보, 열린 API를 적는 설정 | CT-RPC-013~015, 역할을 고르는 테스트 |
| 거부 판정 강화 | 어떤 오류든 거부로 통과한다 | 사유 문구 앞부분 일치로 판정한다 | 거부 테스트 전부 |
| 동기화 경로 관찰 | 어느 경로로 블록을 받았는지 알 수 없다 | 노드 로그나 지표로 경로를 확인한다 | CT-NODE-006, CT-NODE-007 |
| 실행 결과 기록 | 체인, 프로그램 해시와 버전, 하드포크 상태, 서명 방식, 건너뛴 이유가 결과에 없다 | 세 체인 결과를 같은 테스트 ID로 묶고 위 정보를 남긴다 | 전부 |
| 세 체인 일괄 실행 | 한 번에 한 체인만 돌린다 | 세 프로필로 이어 돌리고 결과를 한 표로 모은다 | 전부 |
| 준비물 공유 | 한 파일 안에서 저장한 값(배포 주소, 영수증)을 다른 파일이 쓸 수 없다 | 준비 단계가 남긴 값을 뒤 파일이 이름으로 읽는 기능. 회귀 실행 묶음이 이를 전제로 한다 | 묶음 A, C |

## 3. 두 체인에만 있어 공통에서 뺀 기능

합의 정보 API, 블록 헤더의 합의 정보, 계정 코드 위임, P256 서명 검증은 WEMIX4.0과 StableNet에만 있다. Brioche 보상은 WEMIX3.0과 WEMIX4.0에만 있다. 기본 수수료 상한은 WEMIX3.0과 StableNet에만 있다. 이들은 부록 A에 기존 ID로 정리했다. 계정 코드 위임과 P256은 두 체인 사이에서도 켜는 방법이 달라, 지원 여부와 활성 여부를 나눠 확인해야 한다.
