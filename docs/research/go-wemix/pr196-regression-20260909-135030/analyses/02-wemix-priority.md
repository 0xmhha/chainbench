# go-wemix에서 수행할 기존 테스트: 중요도 순

> ID 표기는 Confluence 원래 명세 ID를 우선한다. 실행 ID는 별도 표기한다. ID 대응은 전체 명세 충족이나 PASS를 뜻하지 않는다. [ID 대응표](/Users/wm-it-25_0220/Work/github/chainbench/docs/research/common-tests/mainnet-dependencies-20260909/analyses/existing-tc-specs.md)

대상은 원본 항목 144개다. 문서 명세 47행과 JSON 97개이며, 기능 중복을 제거한 실행 횟수가 아니다. 실제 대응과 검증 차이는 source-crosswalk.md에서 확인한다.

**아래 목록에는 새 RLP 경계 테스트를 섞지 않았다. 필수 추가 테스트는 additional-tests.md에 별도로 정리한다.** 기존 테스트를 전부 통과해도 PR196의 크기 제한과 체인 정지 문제가 해결됐다는 증거는 되지 않는다.

| 중요도 | 의미 |
|---|---|
| P0 | 변경된 채굴/동기화 경로의 필수 회귀. 추가 경계 테스트와 함께 릴리스 판정 |
| P1 | 거래·상태·복구 등 핵심 회귀와 환경 선행 확인 |
| P2 | 간접 RPC·보상·운영 기능 회귀 |
| P3 | 낮은 직접 영향의 보조 확인 |

중요도와 실행 순서는 다르다. 체인 기동, 계정 준비, 기본 RPC 점검은 P0 경계 테스트의 선행 조건으로 먼저 수행한다. `조건부` 항목은 조건을 해결하기 전 실행 가능하다고 판정하지 않는다.

재검토에서 공통 기능 이식 후보 11개를 복원했다. Anzeon·WBFT 고유 의미의 지원을 뜻하지 않으며, 항목에 명시된 입력·기대값 변경이 필요하다. [재검토 결과](recheck-summary.md)에 변경 근거를 기록했다.

## 적용 시 오판 방지

- direct 5개도 실행 성공을 확인한 것이 아니다. gwemix, preset 키, PoA/etcd, 계정과 실행 자원을 준비해야 한다.
- adapt 89개는 `--chain wemix` 옵션만으로 실행할 수 없다. JSON 내부 env와 applicableChains, 실제 참조하는 EN 노드, chain별 oracle을 수정해야 한다.
- conditional 3개 JSON은 다른 바이너리나 PN 지원, 자금원 등의 전제가 남아 있다.
