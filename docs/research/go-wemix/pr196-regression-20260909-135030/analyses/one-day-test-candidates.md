# PR196 하루 집중 회귀 테스트: 핵심 33개

P1도 핵심만 추려 기존 160개 후보를 **33개 항목**으로 줄였다. 앞서 작성한 116개 하루 계획을 대체한다. **P0 11개 전부, P1 17개, P2 4개, P3 1개**를 수행 대상으로 삼는다. 나머지 127개는 후속 회귀로 남기며 원래 우선순위는 변경하지 않는다.

**시간 재검토 결과: 준비 완료 후에도 약 10~20시간을 계획한다.** 상세 추정은 아래 시간 절을 따른다. 테스트 구현·이식·fixture·환경 준비는 실행 일정 전에 완료해야 한다. 현재 보고서의 테스트는 미실행이며 N-001~N-015도 신규 구현 제안이다. 준비 작업까지 당일에 포함하면 하루 완료를 보장할 수 없다. 33개는 후보 항목 수이며 각 N-항목의 경계값·거래 타입·노드 조합을 포함한 실제 실행 횟수는 더 많다.

## P1을 줄인 기준

- N-008~N-015 8개는 모두 유지한다. 거래 이월·상태 회계·누적 size·RLP·응답 집계·receipt·거부 후 복구·제한 우선순위는 이번 패치와 직접 연결된다.
- 기존 P1 89개 중 9개를 선택했다. 기동·장애 복구, 정상 거래·대납, 잔액 부족 거부, 계약 정상·revert·out-of-gas, snap 동기화를 대표 항목으로 둔다.
- 나머지 기존 P1 80개는 이번 집중 실행에서 미룬다. 일반 RPC의 여러 조회 변형, 서명 실패 조합, 별도 수수료 경계, 여러 장애 토폴로지·부하 조합, 유사 문서와 JSON을 모두 당일에 실행하지 않는다.
- 미룬 항목을 대표 항목의 통과로 대신하지 않는다. 특히 대납 서명 변조 거부, 다양한 baseFee/feeCap 경계, 네트워크 분할은 이번 선택만으로 전부 검증됐다고 볼 수 없다.
- `동일 명세 ID`가 `동일 assertion`을 뜻하지 않는다. P0 nonce 명세를 JSON의 최종 nonce 확인만으로 대체하지 않으며, full/downloader/fetcher 진입도 실제 관측한다.

## 테스트 실행 환경 표기의 의미

아래 `L1`, `L2`, `L3`는 분석 문서 작성 과정에서 테스트 실행 환경을 설명하려고 추가한 약칭이다. 프로젝트의 기존 레이어 구조나 공식 TC 스펙의 분류가 아니다. 우선순위 `P0`~`P3`와도 별개다.

| 표기 | 풀어 쓴 이름 | 의미 |
|---|---|---|
| L1 | 단위 테스트 | 함수나 인코딩 로직을 개별적으로 검사한다. |
| L2 | 프로세스 내부 통합 테스트 | Go 테스트 프로세스 안에서 실제 블록·상태·마이너 등의 객체를 연결해 검사한다. 실제 노드 여러 개를 기동하는 시험과는 구분한다. |
| L3 | 실제 다중 노드 테스트 | 실제 go-wemix 바이너리로 여러 노드를 실행해 전파·동기화·장애 복구를 검사한다. 혼합 버전 항목은 구버전과 패치 버전 노드를 함께 구성한다. |

`L2 → L3`는 프로세스 내부 통합 테스트 후 실제 다중 노드 환경에서도 확인한다는 뜻이다. `L1 → L2`는 단위 검사 후 관련 객체를 연결해 확인한다는 뜻이다. 화살표는 시스템 계층이나 호출 방향을 나타내지 않는다. 앞 단계의 통과만으로 뒤 단계까지 검증됐다고 판단하지 않는다.

이 표기는 필요한 실행 방식을 제안한 것이며, 해당 테스트가 이미 구현되어 있다는 뜻은 아니다.

## 예상 시간 재검토

**기존 8시간 배정은 항목별 소요 시간을 합산하지 않은 목표 예산이었다. 검토 후 약 10~20시간, 8시간 근무일 기준 2~3일로 보정한다.** 구현·이식·fixture가 준비된 상태에서 담당자 1명이 기본적으로 직렬 실행·확인하는 계획용 추정이다. 실측하지 않았으며 신뢰도는 낮다.

| 구분 | 예상 범위 |
|---|---:|
| 기존 18개 실행·확인 | 109~221분 |
| 신규 15개 실행·확인 | 375~735분 |
| 최초 환경 기동·준비 확인 | 30~45분 |
| 최종 증거 대조 | 30~45분 |
| 지연·선별 재실행 여유 | 60~120분 |
| 합계 | **604~1,166분, 약 10~20시간** |

주된 소요 시간은 과거 과대블록 full/snap/import/restart, 혼합 버전 전환, 대형 receipt·snap, 거부 후 회복이다. 기존 전파·동기화·호환 150분 배정은 이 범위를 담기에 부족했다. 구현·빌드·과거 체인 조사·fixture 생성·실패 원인 수정 시간은 별도다.

실행 순서는 환경 확인 → 기본 거래·계약 → 크기 경계 → 전파·동기화·호환 → 장애·이월 복구 → 결과 대조를 유지한다. 독립 환경의 동기화는 먼저 시작할 수 있지만 환경·계정·nonce를 공유하는 시험은 병렬로 수행하지 않는다.

[33개 항목별 예상 시간과 산정 근거](one-day-time-review.md)를 확인한다. 사전 실측으로 가장 긴 실행 경로와 재실행 여유가 480분 이내임을 확인하기 전에는 하루 완료를 확정하지 않는다. 선정 항목과 우선순위는 유지했다.

## 사전 준비와 종료 기준

- 패치 바이너리의 커밋·해시를 고정한다. 원래 분석은 PR head `5a9355` 보존본 기준이다. 최신 패치의 한도·오류·호환 정책이 달라졌다면 N-테스트 기대값을 다시 확인한다.
- 기존 선정 18개 중 기존 구현 후보 3개, JSON 이식 대상 6개, 문서 구현·이식 대상 8개, 조건부 snap 명세 1개다. 기존 구현 후보도 실제 패치 바이너리에서는 미실행이다.
- PoA/etcd genesis, 계정·자금·서명·fee 정책, EN 참조, 기존 시나리오에 필요한 노드 구성을 준비한다. StableNet/WBFT 전용 기대값을 go-wemix용으로 이식한다.
- RLP 경계 fixture, 과거 과대블록, 충분한 길이의 full/snap 데이터, 구버전·패치 버전 환경을 준비한다. N-004·N-005의 호환 정책을 미리 결정한다.
- snap은 실제 snap 진입을 확인한다. full fallback은 snap 통과가 아니다. 조건 미충족이면 BLOCKED로 남긴다.
- 각 분석 키별 PASS / FAIL / BLOCKED / NOT RUN, 커밋, 환경, 실제 시간, 증거 위치를 기록한다. 같은 실행 결과를 재사용해도 각 명세의 기대 결과를 별도로 대조한다.
- 선정 33개를 모두 통과해야 이 집중 회귀 목록 완료로 보고한다. P0 실패·미완료는 배포 판정의 차단 사유로 남긴다. 이 목록의 완료는 전체 160개 회귀 완료를 뜻하지 않는다.

## 후속 회귀 범위

P1 80개, P2 41개, P3 6개를 후속 일정으로 미뤘다. 전체 목록에서 이 문서의 분석 키 33개를 제외한 항목이다. 새로 발견된 실패와 연결된 항목은 원래 우선순위에 따라 다시 포함한다. N-016의 반복 대형 메시지 자원 회복, WebSocket, 별도 체인 전환, 다양한 수수료·서명 거부·장애 조합은 이번 검증 범위 밖이다.

선정·제외 분석 키는 [기계 판독용 목록](one-day-test-selection.json)에 보존했다. 코드를 수정하거나 테스트를 실행하지 않았다.
