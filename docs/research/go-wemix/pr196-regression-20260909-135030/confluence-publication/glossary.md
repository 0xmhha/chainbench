## 문서 안내

[집중 테스트 33개 상세 실행 절차](https://wemade.atlassian.net/wiki/spaces/platfomDev/pages/2979070094/PR196+33)를 읽고 결과를 판정할 때 필요한 용어를 정리한다. RPC 이름과 응답 필드는 실제 조회 결과와 대조할 수 있도록 원래 표기를 함께 적었다.

## 테스트와 결과

| 용어 | 뜻과 확인 방법 |
|---|---|
| 테스트 ID | 기존 명세에서 부여한 번호다. RT-A-2-04처럼 원래 번호를 유지한다. |
| 신규 테스트 N-번호 | 이번 검토에서 추가한 테스트를 구분하는 번호다. 기존 명세의 공식 ID가 아니다. |
| 참조 번호 | TC-052, DOC-C-008 등 자료를 연결하는 분석용 번호다. 기존 명세 ID와 구분한다. |
| P0 / P1 / P2 / P3 | 이 목록의 중요도 구분이다. P0가 가장 높다. 실행 순서와 반드시 같지는 않다. |
| 기존 자동 테스트 | 제공된 테스트 파일을 실행해 정해진 값만 검사하는 절차다. 문서에 적힌 모든 확인 사항을 자동으로 검사한다는 뜻은 아니다. |
| 통과 / 실패 / 판정 보류 / 미실행 | 기대값 일치, 기대값 불일치, 판단 근거 부족, 실행하지 않음을 각각 뜻한다. 일부 조건만 확인했으면 전체 통과로 기록하지 않는다. |
| 경계값 | 제한값 바로 아래, 제한값과 같은 값, 제한값 바로 위의 입력이다. ‘미만’과 ‘이하’를 구분한다. |

## 체인과 노드

| 용어 | 뜻과 확인 방법 |
|---|---|
| 노드 / 상대 노드(peer) | 체인을 저장하고 거래·블록을 주고받는 실행 단위다. 상대 노드는 현재 노드와 연결된 다른 노드다. |
| 블록 생성 노드(BP) | 블록을 만들어 다른 노드에 전달하는 노드다. 연결된 상대 노드 수만으로 모든 BP의 참여를 확인할 수는 없다. |
| 최초 블록 설정(genesis) | 체인 ID, 초기 계정과 체인 규칙 등을 정하는 초기 설정이다. 노드끼리 같은 체인을 검사하는지 확인하는 기준이다. |
| 체인 ID / eth_chainId | 거래 서명 등에 사용하는 체인 식별값이다. RPC 응답을 지정한 체인 ID와 비교한다. 값이 양수인지만 확인해서는 부족하다. |
| RPC / RPC 주소 | 노드의 데이터를 조회하거나 거래를 제출하는 요청 방식과 접속 주소다. eth_getCode, eth_call 등이 RPC 요청 이름이다. |
| 블록 높이 / eth_blockNumber | 체인에서 블록의 순서를 나타내는 번호다. 문서의 H는 노드끼리 비교하기 위해 정한 같은 높이다. |
| 블록 해시 / 거래 해시 | 블록이나 거래를 구분하는 값이다. 같은 높이의 블록 해시가 다르면 다른 블록을 보고 있는 것이다. |
| 정식 체인(canonical chain) | 노드가 현재 기준으로 채택한 블록의 연결이다. 블록을 수신하거나 보관한 것만으로 정식 체인에 반영된 것은 아니다. |
| 체인 분기 | 노드들이 서로 다른 블록의 연결을 기준으로 삼는 상태다. 높이가 같아도 블록 해시가 다를 수 있다. |
| 부모 블록 / 대체 블록 | 부모는 바로 앞 블록이다. 거부된 블록을 대신할 정상 블록은 같은 정상 부모에서 이어져야 한다. |
| stateRoot | 블록 실행 후 전체 계정 상태를 요약한 해시다. 같은 블록을 처리한 노드의 상태가 일치하는지 비교한다. |
| receiptsRoot | 블록에 포함된 거래 영수증 목록을 요약한 해시다. 실행 결과의 일치 여부를 확인한다. |
| 체인 규칙 / 포크(fork) | 지정한 조건부터 적용되는 거래·가스·보상 등의 규칙이다. 여기서 포크는 ‘체인 분기’와 구분한다. |
| Brioche / Croissant | WEMIX의 규칙 변경 이름이다. 대상 설정에 따라 Brioche 보상과 Croissant 이후 블록 생성 여부를 판정한다. |
| etcd / 블록 생성 권한 | WEMIX 노드 사이에서 블록 생성 권한을 관리하는 저장·조정 장치와 그 권한이다. 기존 권한이 반환 또는 회수되어야 다음 생성자가 진행할 수 있다. |
| 생성 권한 만료 | 권한의 유효 조건이 끝나 회수 대상이 된 상태다. N-007에서는 정상 반환 및 노드 중단과 구분해 검사한다. |

## 거래와 컨트랙트

| 용어 | 뜻과 확인 방법 |
|---|---|
| 송신자 / 수신자 / 수수료 대납자 | 각각 거래를 보내는 계정, 전송액을 받는 계정, 수수료를 대신 내는 계정이다. 대납 검사는 세 계정을 구분한다. |
| nonce | 송신 계정별 거래 순서 번호다. 정상 포함 시 증가하며 서로 다른 계정끼리 하나의 순서를 정하지는 않는다. |
| 가스(gas) / gasLimit / gasUsed | 가스는 실행 자원을 계산하는 단위다. gasLimit은 허용량, gasUsed는 실제 사용량이다. 가스 단위 자체는 금액이 아니다. |
| 기본 수수료(baseFee) | 해당 블록에 적용되는 기본 가스 가격이다. 동적 수수료 거래의 실제 가스 가격을 확인할 때 사용한다. |
| 수수료 상한 / 우선 수수료 | 동적 수수료 거래의 maxFeePerGas와 maxPriorityFeePerGas다. 대상 체인에 적용된 규칙으로 실제 가스 가격을 확인한다. |
| effectiveGasPrice | 거래에 실제 적용된 가스 단위당 가격이다. 해당 수수료 방식에서 거래 비용은 gasUsed와 곱해 계산한다. |
| 거래 영수증(receipt) / status | 블록에 포함된 거래의 결과다. status=1은 실행 성공, status=0은 실행 실패다. 블록 포함 전 거부와 구분한다. |
| REVERT | 컨트랙트 실행을 취소하고 해당 실행의 상태 변경을 되돌리는 동작이다. 거래가 블록에 포함될 수 있으며 수수료까지 전부 없어지는 것은 아니다. |
| 가스 소진(out of gas) | 허용된 가스를 모두 사용해 실행이 실패한 상태다. 해당 테스트에서는 실패 영수증과 사용 가스를 함께 확인한다. |
| 컨트랙트 코드 / 입력 데이터 | 체인에 배포된 실행 코드와 호출에 전달하는 데이터다. eth_getCode는 코드 조회, eth_call은 거래를 블록에 넣지 않고 호출 결과를 확인하는 요청이다. |
| 이벤트 로그 | 컨트랙트 실행이 영수증에 남기는 기록이다. 노드 실행 로그와 다르며 영수증 응답의 크기를 늘릴 수 있다. |
| 기본 거래 / 접근 목록 거래 / 동적 수수료 거래 | 각각 Legacy, AccessList, DynamicFee를 뜻한다. 동적 수수료 거래의 type은 0x2다. |
| 수수료 대납 동적 거래 | 별도 계정이 수수료를 내는 거래 유형이다. 검토한 코드에서는 type 22, 16진수로 0x16이다. |
| 가스 추정 / eth_estimateGas | 주어진 상태와 입력으로 거래 실행에 필요한 가스를 추정한다. 실제 실행 사이에 상태가 바뀌면 결과가 달라질 수 있다. |

## 거래 보관과 블록 생성

| 용어 | 뜻과 확인 방법 |
|---|---|
| 거래 풀(txpool) | 노드가 아직 블록에 넣지 않은 거래를 보관하는 곳이다. 노드마다 보유 목록이 다를 수 있다. |
| pending / queued | 거래 풀이 실행 가능한 것으로 분류한 거래와 선행 nonce 누락 등의 이유로 대기시키는 거래다. 크기 제한으로 미포함된 거래가 반드시 queued가 되는 것은 아니다. |
| txpool_status / txpool_content | 거래 풀의 분류별 건수와 상세 목록을 조회한다. 같은 노드의 같은 상태에서 비교한다. |
| 거래 교체 / PriceBump | 같은 계정과 nonce의 새 거래로 기존 거래를 바꾸는 동작과 필요한 수수료 인상 조건이다. 교체가 수락된 뒤 새 블록 생성 작업에서 확인한다. |
| 거래 풀 갱신 | 새 블록과 계정 상태를 반영해 보관 거래를 다시 분류하는 동작이다. 갱신 중 조회한 결과끼리는 일치하지 않을 수 있다. |
| 거래 이월 | 이번 블록에 담지 못한 유효 거래가 이후 블록에 포함되는 것이다. 거래 풀 보관과 새 생성자에게 전달되었는지도 확인한다. |
| 거래 사전 처리 / PrefetchCount | 실제 블록 반영에 앞서 거래 실행에 필요한 작업을 미리 수행하는 기능이다. 값 0은 끔, 양수는 켬으로 구분한다. 임시 계산과 정식 상태 반영을 구분해야 한다. |
| 블록 생성 중간 상태 | 완성 전 블록에 추가한 거래, 계정 상태, 영수증과 누적 크기를 보관한 상태다. 최종 블록 자체와 구분한다. |
| 블록 생성 종료 조건 | N-015에서 크기·가스·거래 수 조건과 별도로 확인하는 생성 종료 기준이다. 생성 마감 조건과 최소 처리 거래 수가 함께 충족되었는지 확인한다. |

## 동기화와 크기

| 용어 | 뜻과 확인 방법 |
|---|---|
| 전체 동기화(full sync) | 블록을 받아 검증·실행하면서 체인 상태를 구성하는 방식이다. 정상 경로 진입과 같은 높이의 상태를 확인한다. |
| 스냅 동기화(snap sync) | 기준 상태를 내려받고 이후 블록을 처리하는 방식이다. snap 설정만으로 실제 수행을 증명할 수는 없다. |
| 기준점(pivot) | 스냅 동기화에서 상태를 맞추는 기준 블록이다. 기준점 이전 자료와 이후 블록 처리 경로를 구분한다. |
| Downloader / Fetcher | 각각 누락 블록을 일괄 동기화하는 경로와 새 블록을 받아 검증·반영하는 경로다. 블록 높이만으로 어느 경로인지 판단하지 않는다. |
| 블록 본문 / 헤더 | 본문에는 거래 목록 등이, 헤더에는 부모 블록·실행 결과를 나타내는 해시와 블록 정보 등이 들어간다. 두 부분의 내용이 서로 맞아야 유효하다. |
| RLP / 인코딩 | 블록·거래·메시지 자료를 정해진 바이트 표현으로 바꾸는 형식과 동작이다. 크기 검사는 실제로 만든 바이트 수를 기준으로 한다. |
| MiB | 1 MiB는 1,048,576바이트다. 8 MiB는 8,388,608바이트, 10 MiB는 10,485,760바이트다. 1,000,000바이트와 1 MiB는 다르다. |
| 블록 수신 상한 / 거래 추가 기준값 | 검토한 패치의 블록 수신은 8 MiB 이하를 허용한다. 거래 추가 계산값은 7,388,608바이트 미만이어야 한다. 두 경계의 비교 조건이 다르다. |
| NewBlock / BlockBodies / GetReceipts | 각각 새 블록 전달, 요청한 블록 본문 응답, 거래 영수증 요청에 쓰는 메시지 이름이다. |
| ETH65 / ETH66 / ETH68 / mir | 블록 자료를 교환하는 프로토콜 형식의 버전과 WEMIX 연결에서 사용하는 프로토콜 이름이다. 실제 연결에서 선택된 이름과 버전을 기록한다. |
| 요청 식별자 | 요청과 응답을 대응시키는 값이다. ETH66/68 응답은 이 값과 목록을 감싸는 바이트까지 포함해 크기를 계산한다. |
| 메시지 본문 크기 / RLPx | 메시지 검사가 확인하는 크기는 RLP 본문의 바이트 수다. 노드 간 전송 계층인 RLPx의 제한과 암호화·압축된 전체 통신량은 별개다. |
| 과대 블록 | 이 문서에서는 실제 RLP 크기가 8 MiB를 초과한 블록이다. 크기 외 조건도 유효하게 준비해야 크기 제한의 효과를 분리할 수 있다. |
