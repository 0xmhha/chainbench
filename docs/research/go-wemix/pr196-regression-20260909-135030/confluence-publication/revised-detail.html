문서 안내

PR196 패치가 블록 생성, 거래 처리, 노드 동기화에 미치는 영향을 확인한다. 총 33개이며 P0 11개, P1 17개, P2 4개, P3 1개로 구성한다. 이 문서는 실행 절차를 설명하며 테스트 결과를 뜻하지 않는다.

기존 테스트 18개의 명세 ID는 그대로 사용한다. 명세 ID가 확인되지 않은 2개는 기존 테스트 이름으로 표시한다. 신규 테스트 15개의 N-번호는 이 문서에서 구분하기 위한 번호이며 기존 명세 ID가 아니다.

용어 설명은 PR196 테스트 용어집에서 확인한다.

공통 준비 사항

  • 운영망과 분리된 WEMIX3.0 테스트망을 사용한다. 노드 버전, 최초 블록 설정, 적용된 체인 규칙, 노드별 역할과 RPC 주소를 기록한다.
  • 계정은 테스트별로 구분한다. 잔액을 비교할 계정에는 다른 거래나 블록 보상이 섞이지 않도록 한다. 비밀키와 인증정보는 결과 문서에 남기지 않는다.
  • 블록 크기와 메시지 크기는 구분해서 측정한다. 이 문서의 기준값은 검토한 PR196 패치인 5a9355 기준이다. 실행할 버전의 제한값이나 비교 조건이 달라졌다면 기대값을 다시 확인한다.
  • 블록 수신 상한은 8,388,608바이트(8 MiB), 메시지 수신 상한은 10,485,760바이트(10 MiB)다. 블록에 거래를 추가할 때 사용하는 별도 기준값은 7,388,608바이트다.
  • 노드 간 비교는 같은 블록 높이 H를 기준으로 한다. 각 노드의 최신 블록을 따로 조회해 비교하면 서로 다른 블록을 비교할 수 있다.
  • 수정 전후 비교에는 같은 체인 설정과 입력 자료를 사용한다. 크기 제한 때문에 거래가 나뉘어 담길 수 있으므로, 버전이 다른 노드가 각각 만든 블록의 해시가 항상 같아야 하는 것은 아니다.
  • 장애나 잘못된 블록을 다루는 테스트는 항목마다 별도 데이터 사본으로 시작한다. 계정과 노드 데이터를 공유하는 테스트는 동시에 실행하지 않는다.
  • 정확한 크기나 처리 경로를 확인할 수 없는 환경에서는 해당 항목을 통과로 기록하지 않는다. 필요한 관측값과 실행 자료를 확보한 뒤 판정한다.

결과 기록과 판정

각 테스트와 하위 조건별로 테스트 ID, 노드 버전, 환경 설정, 입력 자료, 기대값, 실제값, 판정, 근거 자료의 위치를 남긴다. RPC 응답, 거래와 블록의 해시, 거래 영수증, 계정 상태, 관련 로그를 함께 보관한다. 크기 테스트는 노드가 계산한 값과 실제 인코딩한 바이트 수를 각각 남긴다.

  • 통과: 모든 필수 조건을 실행했고 기대 결과가 일치한다.
  • 실패: 실행 결과가 기대 결과와 다르다. 입력 오류와 환경 문제를 구분해 기록한다.
  • 판정 보류: 환경, 처리 경로 또는 적용 정책을 확인할 수 없어 결론을 내릴 수 없다.
  • 미실행: 아직 실행하지 않았다. 일부 조건만 실행했다면 남은 조건을 명시한다.

기존 자동 테스트가 확인하는 범위와 이 문서에서 요구하는 확인 사항은 다를 수 있다. 아래의 ‘판정 주의’를 함께 적용한다. 과대 블록 거부를 확인했더라도 정상 체인이 갈라지거나 동기화가 중단되면 배포 검증을 통과한 것으로 처리하지 않는다.

권장 실행 순서

  1. 체인 ID와 노드 기동을 확인한다. 정상 거래, 컨트랙트, 실패 거래, 수수료 대납, 가스 추정과 보상 조회로 기준 상태를 확보한다.
  2. 블록과 거래의 크기 경계 및 실패 처리(N-001, N-002, N-009~N-012, N-015)를 확인한 뒤 실제 노드의 블록 생성과 전파(N-003)를 확인한다.
  3. 정상 동기화 후 과거 블록, 혼합 버전, 대형 메시지와 응답, 과대 블록 거부를 확인한다(N-004~N-006, N-013, N-014).
  4. 거래 순서, 블록 생성 권한, 거래 이월과 노드 장애를 확인한다(N-007, N-008 포함). 거래 풀 조회 결과도 같은 단계에서 수집한다.

RT-A-2-04 / TX-010 · 계정별 거래 순서 확인

우선순위: P0. 참조: DOC-C-008.

준비: 블록 생성을 제어할 수 있는 테스트망과 자금이 있는 송신 계정 2개를 준비한다. 거래 풀에 모든 거래를 보관할 수 있어야 한다.

  1. 각 계정의 시작 nonce를 기록한다. 연속된 nonce의 거래를 순서대로 제출하는 경우와 역순으로 제출하는 경우를 나누어 실행한다.
  2. 역순 제출은 모든 거래가 거래 풀에 도착한 것을 확인한 뒤 블록 생성을 재개한다.
  3. 거래 영수증과 블록의 거래 목록을 수집한다. 같은 계정의 거래를 블록 번호와 블록 내 순서로 정렬해 nonce와 대조한다.

기대 결과: 각 계정의 거래가 nonce 순서대로 정식 체인에 한 번씩 포함된다. 서로 다른 계정 사이에는 하나의 공통 순서를 요구하지 않는다.

판정 주의: 최종 nonce 값만으로 거래의 실제 포함 순서까지 확인했다고 판단하지 않는다.

기존 명세: RT-A-2-04 / TX-010

RT-A-2-06 · 잔액이 부족한 거래의 거부 확인

  3. 실제 연결에서는 전송 규격에 맞는 정상 블록을 NewBlock으로 전파한다. 8 MiB에 가까운 유효 블록과 작은 블록을 모두 확인한다.

기대 결과: 10,485,760바이트를 초과할 때 크기 초과로 거부한다. 정상 블록은 연결이 유지된 채 수락되며 다음 블록도 반영된다.

판정 주의: 크기가 상한과 같아도 형식이 잘못되면 다른 오류로 거부될 수 있다. 암호화·압축을 포함한 전체 통신량은 여기서 검사하는 메시지 크기와 다르다. 실제 전송은 RLPx의 별도 한도도 지켜야 한다.

신규 테스트 N-007 · 블록 생성 권한 반환과 후속 블록 확인

우선순위: P0.

준비: etcd로 블록 생성 권한을 관리하는 실제 WEMIX3.0 환경을 사용한다. 거래 사전 처리 기능을 끈 경우와 켠 경우를 나누어 확인한다.

  1. 크기 제한으로 거래 추가가 종료되는 블록을 생성한다.
  2. 정상 완료, 생성 도중 노드 중단, 생성 권한 만료를 각각 별도 환경에서 확인한다.
  3. 권한 반환 또는 회수 여부와 다음 생성자의 블록 생성을 확인한다. 미포함 거래의 후속 포함 여부를 해시와 nonce로 추적한다.

기대 결과: 정상 완료 시 블록 저장과 전파가 끝나고 권한이 반환된다. 장애 조건에서도 권한이 회수되어 다음 생성자가 블록을 만든다. 유효한 미포함 거래는 N-008의 보관 조건에서 누락이나 중복 없이 처리된다.

판정 주의: 블록 생성 권한 만료는 검사해야 할 상태 조건이다. 수정 전후의 같은 장애 조건을 비교해 패치 영향과 기존 동작을 구분한다.

신규 테스트 N-008 · 미포함 거래의 이월과 교체 확인

우선순위: P1.

준비: 여러 계정의 연속 nonce 거래를 준비한다. 잔액, 가스, 수수료와 거래 풀 용량을 충분히 확보한다. 다른 거래의 유입이나 보관 정책 때문에 거래가 삭제되지 않게 한다.

  1. 첫 블록이 크기 제한에 도달하도록 거래를 제출하고 해시와 nonce를 기록한다.
  2. 새 블록을 반영한 거래 풀에서 미포함 거래를 확인한다. 같은 nonce의 거래를 교체할 때는 수수료 인상 조건을 충족하고 교체 수락을 확인한다.
  3. 교체가 수락된 뒤 새 블록 생성 작업을 시작한다. 생성자를 바꾼 경우에는 새 생성자가 거래를 받았는지 확인한다. 후속 블록의 거래 순서와 영수증을 대조한다.

기대 결과: 크기 제한만을 이유로 유효 거래가 거래 풀에서 삭제되지 않는다. 후속 블록에 계정별 nonce 순서로 한 번씩 포함된다. 교체한 nonce에는 새 거래만 포함된다. 같은 블록을 반영한 노드의 상태와 영수증이 일치한다.

판정 주의: 미포함 상태에서는 영수증이 없어야 한다. 앞선 큰 거래 때문에 블록에 여유가 남는 것은 검토한 패치의 거래 추가 종료 방식에 따른 결과일 수 있다. 수정 전후의 블록 배치가 같을 필요는 없다.

신규 테스트 N-009 · 거부된 거래와 실행 실패 거래의 상태 확인

우선순위: P1.

준비: nonce 오류, 잔액 부족, 블록 가스 부족, 허용되지 않은 거래 유형을 각각 준비한다. 별도로 블록에 포함 가능한 REVERT 거래와 가스 소진 거래를 준비한다.

  1. 크기 검사에 통과하는 무효 거래와 크기를 초과하는 무효 거래를 구분한다. 각 거래 뒤에는 작은 정상 거래를 둔다.
  2. 처리 전후의 계정 상태, nonce, 포함 거래 수, 누적 크기, 영수증과 가스 사용 내역을 기록한다.
  3. 정상 거래, REVERT 거래와 가스 소진 거래도 각각 실행한다. 수정 전후의 오류별 처리 결과를 비교한다.

기대 결과: 크기 검사를 통과했지만 적용 단계에서 거부된 거래는 포함 목록과 누적 크기를 늘리지 않으며 계정 상태가 복원된다. 유효하게 포함된 실행 실패 거래는 크기와 영수증에 반영되고 nonce 및 가스 비용도 처리된다.

판정 주의: 모든 내부 가스 집계가 일괄 복원된다고 가정하지 않는다. 오류별 기존 규칙과 비교한다. 크기 초과로 먼저 종료된 경우에는 뒤의 작은 거래가 반드시 포함되어야 하는 것은 아니다. 내부 처리 표시만으로 블록 포함을 판단하지 않는다.

신규 테스트 N-010 · 블록 생성 작업 변경 후 크기와 상태 확인

우선순위: P1.

준비: 여러 거래가 반영된 블록 생성 중간 상태와 서로 다른 추가 거래를 준비한다. 중간 상태의 크기와 처리 결과를 비교할 수 있어야 한다.

  1. 중간 상태를 복사한 뒤 원본과 복사본에 서로 다른 정상 거래를 추가한다.
  2. 새 블록 수신으로 기존 작업을 중단하는 경우, 생성 후보를 다시 제출하는 경우, 새 블록 생성 작업을 시작하는 경우를 각각 확인한다.
  3. 각 작업의 누적 크기와 계정 상태, 영수증을 비교한다. 폐기된 작업의 유효 거래가 후속 정식 블록에 포함되는지도 확인한다.

기대 결과: 복사 직후 누적 크기는 같고 정상 거래 추가 후에는 각 작업의 결과가 따로 유지된다. 새 작업의 크기는 새 헤더를 기준으로 시작하며 이전 블록 크기가 더해지지 않는다.

판정 주의: 복사한 영수증의 내부 로그를 직접 변경하는 등 정상 거래 처리와 다른 조작까지 독립성을 요구하지 않는다. 거래의 후속 포함은 N-008의 거래 풀 보관 조건에서 확인한다.

신규 테스트 N-011 · 거래 유형과 읽기 방식별 블록 크기 확인

우선순위: P1.

준비: 대상 체인에서 허용된 기본 거래, 접근 목록 거래, 동적 수수료 거래, 수수료 대납 동적 거래(type 22)를 준비한다.

  1. 같은 거래를 직접 생성·서명한 경우, 바이너리로 저장했다 읽은 경우, RLP로 읽은 경우를 비교한다. 거래 해시가 같은지 확인한다.
  2. 작은 유형 지정 거래를 다수 넣은 블록과 거래별 허용 크기에 가까운 거래를 넣은 블록을 각각 생성한다.
  3. 거래와 블록의 계산 크기를 기록하고, 완성 블록을 별도로 인코딩한 실제 크기와 비교한다.

기대 결과: 같은 거래는 읽기 방식에 관계없이 같은 해시와 실행 결과를 유지한다. 완성 블록의 RLP 크기는 8 MiB 이하이다.

판정 주의: 거래 자체의 계산 크기와 블록 안에서 감싸진 거래의 크기가 항상 같지는 않다. 차이를 실제 바이트 수로 기록하고 1,000,000바이트의 여유가 충분한지 확인한다.

신규 테스트 N-012 · 여러 블록 본문 응답의 크기 확인

우선순위: P1.

준비: 응답에 누적한 본문 크기가 2 MiB 바로 아래인 상태와, 이어서 추가할 8 MiB 이하 정상 블록의 본문을 준비한다.

  1. 해당 블록들을 한 요청으로 조회한다.
  2. ETH65의 본문 목록과 ETH66/68의 요청 식별자를 포함한 응답을 각각 인코딩한다. 메시지 전체 RLP 크기를 측정한다.
  3. 수신 노드의 응답 수락을 확인한다. 한 응답에서 빠진 블록은 다시 요청해 모두 받는지 확인한다.

기대 결과: 정상 응답이 10 MiB를 넘지 않으며 요청한 모든 블록 본문을 받을 수 있다.

판정 주의: 본문 합계만으로는 10 MiB 미만이어도 목록과 요청 식별자에 필요한 바이트가 추가된다. 이 테스트는 그 여유를 확인한다. 상한 초과가 이미 발생했다고 가정하지 않는다.

신규 테스트 N-013 · 대량 로그 영수증과 스냅 동기화 확인

우선순위: P1.

준비: 허용된 블록 가스 안에서 이벤트 로그를 많이 남기는 거래를 준비한다. 완성 블록은 8 MiB 이하여야 한다.

  1. 한 블록의 영수증 묶음이 큰 경우와, 응답 누적 크기가 2 MiB 바로 아래에서 다음 묶음을 추가하는 경우를 각각 만든다.
  2. GetReceipts로 조회하고 영수증 응답의 실제 RLP 크기를 측정한다.
  3. 같은 자료로 수정 전후 노드의 수신과 스냅 동기화를 비교한다. 10 MiB에 도달할 수 없다면 체인 가스 한도에서 가능한 최대량과 근거를 기록한다.

기대 결과: 정상 체인의 영수증을 받아 동기화가 완료된다. 메시지 크기 제한으로 연결 해제와 같은 요청의 재시도만 반복되지 않는다.

판정 주의: 블록이 8 MiB 이하라는 사실만으로 영수증 응답도 작다고 판단하지 않는다. 반대로 가스 규칙을 위반한 자료로 상한 초과를 만든 결과를 정상 체인의 결함으로 기록하지 않는다.

신규 테스트 N-014 · 과대 블록 거부 후 정상 블록 처리 확인

우선순위: P1.

준비: 크기 외의 헤더와 본문 조건이 유효한 과대 블록을 준비한다. 같은 정상 부모에서 이어지는 정상 대체 블록과 후속 블록도 준비한다.

  1. 블록 전체 전달, 해시 공지 후 본문 요청, 누락 블록 일괄 동기화 경로로 과대 블록을 각각 전달한다.
  2. 각 경로를 별도 상태에서 실행한다. 과대 블록 거부 후 정상 상대 노드가 정상 대체 블록과 후속 블록을 전달하게 한다.
  3. 정식 체인의 블록, 계정 잔액과 영수증을 확인한다. 기준 높이 H의 블록 해시와 stateRoot를 정상 노드와 비교한다.

기대 결과: 과대 블록은 정식 체인에 반영되지 않는다. 정상 대체 블록으로 진행하고 노드 간 상태가 일치한다.

판정 주의: 거부된 블록 때문에 잔액이 바뀌거나 그 블록이 정식 거래 영수증의 근거가 되어서는 안 된다. 정상 대체 블록은 거부된 블록의 자식이 아니라 정상 부모에서 이어져야 한다.

신규 테스트 N-015 · 블록 생성 종료 조건 확인

우선순위: P1.

준비: 거래 사전 처리 기능을 끈 경우와 켠 경우를 나누어 확인한다. 각 방식에 실제 적용되는 종료 조건을 기록한다.

  1. 가스 한도 도달, 크기 한도 도달, 블록 생성 종료 조건 충족, 거래 수 상한 도달을 각각 먼저 발생시키는 입력을 준비한다.
  2. 어떤 조건으로 거래 추가가 끝났는지 확인한다. 블록 생성 종료 조건은 최소 처리 거래 수 등 함께 요구되는 조건도 충족시킨다.
  3. 완성 블록의 유효성과 적용 한도를 확인한다. 수정 전후 노드의 기존 종료 규칙도 비교한다.

기대 결과: 각 조건에서 거래 추가를 정상 종료하고 유효한 블록을 만든다. 크기가 먼저 한도에 도달하면 가스가 남아도 종료할 수 있다.

판정 주의: 적용되지 않는 거래 수 제한을 새 요구 사항으로 추가하지 않는다. 모든 종료 조건의 검사 순서가 같다고 가정하지 않는다. 실행 기록에는 실제로 작동한 조건을 남긴다.
