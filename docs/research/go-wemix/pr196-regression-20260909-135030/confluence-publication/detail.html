문서 범위

집중 테스트 33개: P0 11개, P1 17개, P2 4개, P3 1개. 아직 구현·이식 또는 실행이 필요한 후보이며 PASS 결과가 아니다. 준비 완료 후 약 10~20시간(미실측)을 계획한다. 구현·빌드·데이터 준비·실패 수정 시간은 별도다.

기존 명세 ID는 유지했다. N-001~N-015는 신규 테스트이며 제안 추적 번호다. TC-xxx / DOC-C-xxx는 분석에서 부여한 내부 참조 키다. 명세 ID 미확인은 원래 테스트가 없다는 뜻이 아니다.

공통 실행 규칙

- 실제 노드는 운영망이 아닌 격리 WEMIX 테스트 환경에 구성한다. 커밋·바이너리 해시·genesis·활성 fork·gas/tx/pool 한도·prefetch·블록 간격·token TTL·노드 역할을 실행 기록에 고정한다. 계정은 용도별로 분리하고 비밀키·인증정보는 결과 문서에 저장하지 않는다.

- L1/L2/L3는 프로젝트 레이어가 아니라 이 문서에서 사용한 실행 환경 약칭이다. 아래는 단위 검사, 프로세스 내부 통합 검사, 실제 다중 노드 검사로 풀어 쓴다. 내부 객체 검사만으로 token·전파·동기화를 통과시키지 않는다.

- 신규 경계 테스트의 8 MiB, 10 MiB, packing 7,388,608 byte는 보존 PR head 5a9355 기준이다. 실행 전 최신 패치에서 해당 상수와 비교 연산을 확인한다. 달라졌으면 기대값을 버전별로 기록하고 재검토한다.

- 정상 작은 입력과 경계 입력을 구분하고 base/head 비교는 같은 genesis·입력·fork 조건에서 실행한다. 채굴 순서·블록 hash가 버전별로 항상 같아야 한다고 요구하지 않는다. 같은 canonical 블록을 받은 노드끼리 hash/root를 비교하고, 버전별 정상 실행 결과는 의도된 packing 차이를 제외해 비교한다.

- 동기화 fixture·RLP fixture·구버전 바이너리·계측·이식본을 미리 준비한다. 존재하지 않는 테스트 함수명이나 실행 명령을 만들어 적지 않는다. 실제 구현 후 실행 파일/함수/명령을 결과에 연결한다.

- 장애·txpool·생산자 교체 시험마다 원본 DB를 보존하고 복사본/깨끗한 환경으로 초기화한다. 공유 계정·nonce·DB를 동시에 수정하는 시험은 병렬로 수행하지 않는다.

- 시간 제한과 복구 SLA는 실행 전에 실제 블록 간격·TTL·fixture 크기를 기준으로 고정한다. 시간이 초과되면 로그를 보존하고 TIMEOUT 원인을 분류한다. 자동으로 PASS나 제품 결함으로 단정하지 않는다.

결과와 증거

각 하위 입력에 실행 번호, 명세 ID, 분석 키, 커밋, 환경, 입력 fixture 해시, 시작/종료 시각, 기대값, 실제값, PASS/FAIL/BLOCKED/NOT RUN, 로그 위치를 남긴다. 경계 시험은 내부 추정 size와 독립 RLP 인코딩 길이를 모두 보존한다. 정상·거부·회복 단계의 RPC 결과, transaction hash, block hash, receipt, 관련 상태 값을 checkpoint별로 저장한다.

원본 JSON의 제한된 assertion 통과와 아래 보강 검증 통과는 별도 필드로 기록한다. 보강은 기존 파일에 이미 구현돼 있다는 뜻이 아니다. 기대한 거부를 재현했더라도 N-004·N-005에서 배포 정책 위반·체인 분기가 확인되면 “재현 성공 / 배포 검증 실패”로 구분한다. 알려진 문제의 재현을 배포 가능 PASS로 바꾸지 않는다.
