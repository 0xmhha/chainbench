# chainbench Web UI 화면 디자인

이 문서는 [동작 명세](web-ui-spec.md)의 화면을 구현하기 위한 디자인 기준이다.
요구 범위·권한·API·인수 기준을 바꾸지 않는다. 구성 폼의 필드와 허용값은 엔진 계약이
정하며, 이 문서는 화면 배치·표현·상호작용을 정한다.

## 공통 화면

데스크톱은 224px 왼쪽 내비게이션, 64px 상단 workspace 바, 본문과 선택적 상세 패널로
구성한다. 본문 최대 폭은 1440px이며 좌우 여백은 24px이다. 작은 화면에서는 내비게이션을
접고 목록에서 상세 화면으로 이동한다. 실제 작업 상태는 화면 이동이나 패널 닫기와
무관하게 유지한다.

왼쪽 항목은 Dashboard, Chains & Workspaces, Tests, Monitoring, History, Settings이다.
상단에는 현재 workspace, 선택한 체인, 서버 연결 상태, 로그인 사용자와 역할을 표시한다.
체인이 선택되지 않은 상태에서는 체인 선택을 안내한다. 설정·배포 화면과 실행 관측 화면에
동일한 workspace·network 선택 상태를 사용한다.

본문 제목 아래에는 한 문장의 설명을 두고 오른쪽에는 주 동작 하나를 배치한다.
표 행을 선택하면 상세 패널이 열린다. 상세에는 Summary, Configuration, Events 등 실제
자료가 있는 탭을 제공한다. 빈 탭이나 성공하지 않은 작업을 성공 상태로 꾸미지 않는다.

## 시각 기준

기본 테마는 어두운 운영 화면이다. 색만으로 상태를 구별하지 않고 라벨과 아이콘을 함께
쓴다. 본문은 시스템 sans-serif, ID·경로·로그·숫자 열은 시스템 monospace를 사용한다.
기존 이벤트 화면처럼 모든 텍스트를 monospace로 표시하지 않는다.

| 토큰 | 값 | 용도 |
|---|---|---|
| background | `#0b1018` | 페이지 배경 |
| surface | `#121b28` | 카드·표·사이드 패널 |
| surfaceRaised | `#192536` | 선택·hover·입력 요소 |
| border | `#334155` | 카드·입력 경계 |
| text | `#f1f5f9` | 제목·주요 값 |
| textMuted | `#a8b5c8` | 설명·메타데이터 |
| accent | `#93c5fd` | 주 동작·선택·포커스 |
| success | `#6ee7b7` | 검증 성공·실행 중인 정상 노드 |
| warning | `#fcd34d` | interrupted·관측 누락·부분 실패 |
| danger | `#fca5a5` | 실패·철회·초기화·삭제 |

간격은 4/8/12/16/24/32px, 입력 높이는 최소 40px, 버튼은 최소 40px이다.
카드 모서리는 10px, 표는 행 높이 48px을 기준으로 한다. 본문 기본 크기는 14px,
섹션 제목은 18px, 페이지 제목은 26px이다. 키보드 포커스는 2px 외곽선으로 표시한다.
정보를 작은 저대비 텍스트나 hover만으로 숨기지 않는다.

## 화면별 구성

| 화면 | 본문 구성 | 상세·보조 영역 |
|---|---|---|
| Dashboard | 실행 중 작업, 노드 상태, 최근 결과, 관측 누락 요약 | 선택한 작업의 진행·부분 효과·오류 |
| Chains & Workspaces | workspace 목록, 체인 목록, 프리셋 선택과 구성 폼 | effective 값·원본 revision·선택 바이너리의 출처와 지원 범위 |
| Tests | 케이스 목록, 구조 편집기, 실행 준비 | 선택 statement의 인자·참조·검증 오류 |
| Monitoring | 실행·network 선택, 노드 표, metric 차트, 이벤트 | 선택 시점의 로그와 관측 범위 |
| History | 검색·필터, 실행 결과 표, 비교 대상 선택 | 상세 판정·차이·내보내기·권한 있는 삭제 |
| Settings | 사용자·역할, 본인 자격증명, 자산·플러그인 | 메타데이터·검증 결과·철회 영향 |

화면에 `live`라고 표시하려면 해당 연결 또는 관측의 현재 상태가 확인돼야 한다.
서버에 연결됐다는 사실과 노드가 정상 실행 중이라는 사실을 서로 다른 표시로 구분한다.

## 구성과 배포

체인 구성은 프리셋 선택 → 필수 값 설정 → 선택 항목 추가 → 검증 → 저장 흐름이다.
각 필드는 값을 직접 설정했는지, 프리셋에서 상속했는지, 엔진 기본값인지 표시한다.
선택 항목은 그룹별 접기 영역에 두고, 추가한 항목은 삭제해 기본값으로 되돌릴 수 있다.
서버가 허용하지 않는 필드나 옵션은 실행 선택지로 제시하지 않는다.

배포 전에는 같은 화면에서 계획을 검토한다. 대상 호스트·노드·경로·포트, 문서 revision,
바이너리 식별 정보, 실행자의 credential binding, 자원 충돌, 유지/정리 선택을 보여 준다.
검증 오류는 해당 필드와 페이지 상단 요약에 함께 표시하고, 서버 접근 성공과 구성 검증
성공을 별도로 표시한다.

배포가 시작되면 job 상세로 이동한다. 단계별 상태와 실패한 대상, 이미 반영된 효과를
보여 주며, 브라우저를 닫아도 작업이 계속된다는 점을 해당 위치에서 안내한다.

## DSL 편집

왼쪽에는 현행 DSL의 statement 트리를, 가운데에는 선택한 statement의 계약 기반 폼을
표시한다. 구조 추가·삭제·이동은 선택 항목 옆의 버튼과 키보드 조작으로도 가능해야 한다.
드래그만으로 편집하게 만들지 않는다. 등록된 동작·단언·리더와 유효한 노드·변수 참조를
검색해 선택할 수 있고, 각 오류는 statement 경로를 표시하며 해당 항목으로 이동한다.

직렬화 미리보기는 읽기 보조 영역이다. 전체 현행 DSL을 클릭으로 작성·수정하는 기능을
텍스트 편집기에 맡기지 않는다. import 결과는 저장 전 검증·마이그레이션·보존되지 못한
정보를 확인할 수 있게 한다.

## 상태·차트·히스토리

상태 라벨은 서버가 반환하는 상태를 그대로 의미 있게 표현한다. 요청 전송 성공을 작업
성공으로 표시하지 않는다. 취소 요청 중, 취소 완료, 정리 실패와 작업 실패를 구분한다.
attach 노드는 소유·제어 범위를 표시하고 지원하지 않는 제어 버튼을 비활성화하며 이유를
설명한다.

차트의 공통 시간 선택은 이벤트와 로그에도 적용한다. 원본·집계 해상도와 데이터가 없는
구간을 표시하며, 관측 누락을 0 값이나 끊김 없는 선으로 보간하지 않는다. 노드·metric을
선택하면 단위와 수집 시점을 읽을 수 있어야 한다.

히스토리 비교에서는 먼저 호환 여부를 확인한다. 비교 불가 사유를 표시하고 무관한
metric을 같은 축에 놓지 않는다. 결과 삭제와 초기화는 대상·영향을 확인하는 별도 동작으로
구분한다. 권한·소유권 거절 사유는 UI와 직접 API의 의미가 같아야 한다.

## 브라우저 검증

기능별 인수 증거와 함께 좁은 화면, 키보드 이동·포커스, 목록과 상세의 이동,
필드 오류 이동, 로딩·빈 상태·연결 끊김, 현재 선택과 실제 작업 대상의 일치를 확인한다.
최종 화면은 실제 Go 임베드 번들로 검사한다. 목업이나 스크린샷만으로 인수 완료를
판정하지 않는다.
