## 1. 어디까지 왔나

브랜치 **`refactor/design-v3`** 에 커밋 19개. 검증은 매 커밋마다:
`go build ./...` · `go vet ./...` · `go vet -tags e2e ./...` · `gofmt -l internal/ cmd/` ·
`go test ./...` **58/58**.

설계 문서 셋이 `architecture/design-v3/` 에 있다. **읽는 순서가 있다.**

1. [`measurement-2026-09-21.md`](architecture/design-v3/measurement-2026-09-21.md) — 실측만.
   닫은 세 계획의 수치를 하나도 가져오지 않았다.
2. [`direction.md`](architecture/design-v3/direction.md) — 방향과 결정. **§8·§13·§14 가 이름에
   대한 판단의 근거**이고, 두 번 틀렸다가 고친 기록이 같이 있다.
3. [`chain-as-a-run-dimension.md`](architecture/design-v3/chain-as-a-run-dimension.md) — 공통 TC
   한 벌이 세 체인에 도는 문제. **§3 이 대상을 정정한 자리**다(209개가 아니라 공통 TC 76개).

`direction.md` §6 의 계획표에서 1~5 는 닫혔고 6은 취소, **남은 것은 7(큰 덩어리)뿐이며
"요구가 생기면" 으로 두었다.**

## 3. 래칫이 무엇을 지키는지 — 먼저 읽을 것

이 브랜치가 더한 검사들이다. **문서를 손으로 쫓지 말고 이것들이 말하게 하면 된다.**
`preset` 패키지를 옮길 때 다섯이 한 번에 울려 고칠 목록을 만들어 줬다.

| 검사 | 무엇을 막나 |
|---|---|
| `arch.TestPackageTreeBodyIsMeasured` | 패키지별 줄 수 70개 + 빠진 패키지. 틀리면 `python3 scripts/refresh-package-tree.py` |
| `arch.TestPackageTreeSectionsSumTheirOwnEntries` | 절 제목이 그 절의 합과 다른 것 |
| `chainsetup.TestEveryVerbDeclaresWhatItNeeds` | 동사가 선행 조건을 선언하지 않는 것. **"필요 없다" 도 이유를 적어야 한다** |
| `dsl.TestSchemaV2NestedObjectsMatchTheirTypes` | 스키마 중첩 객체가 파서 타입과 어긋나는 것 |
| `TestEveryCommandATestInvokesExists` | 테스트가 없는 명령을 부르는 것 |
| (기존) `arch.TestNoUpwardDependency`·`TestNamesDoNotCollide`·`TestEveryPackageIsPlaced` | 레이어·이름·배치 |

**빚 목록 둘은 줄기만 한다**: `chainsetup` 의 `verbNeeds` 면제 사유, `cmd/chainbench` 의
`invocationDebt`. 늘리려면 이유를 적어야 하고, 낡으면 검사가 걸린다.

## 4. 바로 이어갈 수 있는 것

§0 이 10건이다. **손이 가장 적고 값이 분명한 순서**로 셋만 꼽는다.

1. **죽은 명령을 부르는 e2e 둘** — `invocationDebt` 가 무엇이 걸려 있는지 적고 있다.
   go-wemix·go-wbft 바이너리가 있는 기계에서만 검증된다.
2. **N3 의 빚 둘** — 노드별 `server:` 배치(`chainsetup/steps_place.go:195` 가 이름을 대고 거절),
   BLS 를 패밀리에 묻지 않고 늘 파생(`steps_keys.go`). 후자는 **정합성이 아니라 표현** 문제임을
   확인해 뒀다.
3. **메인넷 트랙 — HEAD 바이너리로 L1 재실행** — 함대와 빌드를 다시 만들어야 한다(§2).

## 5. 이 세션에서 배운 것 — 되풀이하지 말 것

- **낱말은 갈래로 짓는다, 종류로 짓지 않는다.** `HardforkPreset` 으로 갔다가 `ChainPreset` 으로,
  다시 패키지 `chainpreset` → `preset` 으로 두 번 고쳤다. 판정 기준은 하나다 — 그 문서가 담은
  최상위 키 중 종류에 고유한 것이 몇 개인가(`wemix-upgrade.yaml` 은 11 중 1이었다).
- **대량 치환은 영어 낱말까지 바꾼다.** 지역 변수 `preset` → `keys` 로 주석 37줄이 "a keys key
  set" 이 됐다. 치환 뒤에는 **주석만 따로 확인**한다.
- **변이 테스트는 변이가 적용됐는지부터 확인한다.** gofmt 정렬 때문에 문자열 치환이 빗나가
  변이 셋이 전부 "통과" 로 보인 적이 있다. 파일이 실제로 바뀌었는지 먼저 단언한다.
- **`go vet ./...` 만으로는 부족하다.** 게이트 뒤 테스트는 `-tags e2e` 로만 컴파일된다. 헬퍼를
  지우고도 모를 뻔했다.
- **문서가 "완료" 로 적혀 있어도 게이트를 읽는다.** `N2~N6` 을 `◐` 로 믿고 측정했다가 틀렸다 —
  판정에 쓴 잣대가 그 항목의 게이트가 아니었다.
