## 2. 다음 작업 — 순서와 목적

순서는 2026-10-22 결정을 따른다. 각 단계에 목적, 범위, 끝나는 조건, 시작 전에 사용자에게
받을 결정을 적는다. **결정 항목은 내가 정하지 않고 사용자에게 하나씩 묻는다.**

### 2-1. Web UX 후속 (다음에 바로 할 일)

**목적.** 첫 묶음에서 미룬 것을 끝내 Web UI 리팩토링을 닫는다. 판단 기준은 그대로
`web/PRODUCT.md`다. 실패를 본 사람이 원인까지 한 번에 가는지가 여전히 가장 중요한 질문이다.

**범위.** 아래 순서를 권한다. 앞의 것이 뒤의 것보다 사용자 영향이 크다.

1. **체인 구성 폼 정리** (`/chains`, 이번 범위에서 일부러 뺀 것)
   - 라벨에 스키마 경로가 그대로 보인다(`web/src/DeploymentFields.svelte`).
     스키마의 title을 라벨로 쓰고 경로는 힌트로 내린다.
   - fieldset이 3~5단으로 겹친다. 선택 그룹은 "추가" 메뉴 하나 뒤로 숨기고 목록-상세로 바꾼다.
   - 큰 흐름 변경이므로 `web/CLAUDE.md`대로 `/impeccable shape`로 먼저 설계한다.
2. **좁은 화면**
   - 700px 이하에서 로그 레벨이 색으로만 구분된다. 글자를 같이 보인다.
   - 단언 표에서 긴 숫자가 줄을 넘는다.
   - 필터 칩 높이가 30px이다. 터치 대상으로 작다.
3. **서로 어긋난 상태 표시**
   - `/history`, `/monitoring`, 좁은 화면 첫 로딩에서 "불러오는 중", "비어 있음", "연결됨"이
     동시에 또는 번갈아 보인다.
   - `/tests`(DSL 편집기)와 `/settings`(매니페스트)에서 "처리 중…"이 멈춰 있다는 보고가 있다.
     재현하지 못했고 원인을 모른다.
4. **주소로 가리키기**
   - 실행·테스트·시각을 URL로 가리킬 수 없다. 지금은 화면 안 상태라서 링크를 공유하지 못한다.
   - 대시보드의 실행 ID가 링크가 아니다.
5. **작은 것**
   - 작업 취소와 자격증명 폐기가 `window.confirm`을 쓴다(`web/src/MonitorPanel.svelte`,
     `web/src/CredentialManager.svelte`). 대상과 되돌릴 수 없음을 화면 안 확인으로 보인다.

**끝나는 조건.** `web/CLAUDE.md`의 "끝내기 전에"를 모두 지난다. 화면을 실제로 띄워
데스크톱 폭과 좁은 폭에서 보고, critique와 audit를 돌려 지적을 고치고, SPA를 다시 빌드해
함께 커밋한다. 묶음 끝에 critique 점수를 다시 매겨 이 문서의 24/40과 비교한다.

**시작 전에 받을 결정.**
- 위 다섯 묶음을 PR 하나로 할지, 체인 구성 폼만 따로 뺄지.
- URL 상태(4번)를 어디까지 할지. 실행·테스트·시각만인지, 필터까지인지.

**이번 변경 때문에 특히 볼 것.** #458은 화면 구조를 많이 바꿨다. 아래 3절의 브라우저 인수

## 3. 확인하지 못한 것

돌려 보지 않은 것을 통과로 세지 않는다.

- **브라우저 인수 스크립트**(`tests/webui/browser_*.mjs`)를 #458 뒤에 돌리지 않았다. 실제 체인이
  필요하기 때문이다. 스크립트가 쓰는 선택자와 문구(4절)는 지키도록 고쳤지만, 지켰는지는
  실행으로 확인하지 않았다.
- **실데이터가 있는 작업 상세와 대시보드**를 보지 않았다. 화면 확인은 합성 기록(가짜 네트워크
  기록과 세션 기록)으로 했다. 실제 실패 실행에서 타임라인이 로그를 올바른 노드·시점으로
  여는지는 확인하지 않았다.
- **P1 수정 뒤 critique 점수**를 다시 매기지 않았다(1절).
- **옛 기록의 동작**은 단위 테스트로만 확인했다. `startedAt`이 없는 기록은 실행 전체 범위로
  열리고 그 사실을 화면에 적는다.

## 4. 바꾸면 안 되는 계약

### 브라우저 인수 스크립트가 기대는 것

`tests/webui/browser_*.mjs`가 아래를 찾는다. 이름이나 구조를 바꾸면 2-4 단계에서 깨진다.

- `data-testid`: `run-timeline`, `run-cause`, `job-state`, `job-failed-phase`, `job-effects`,
  `job-disposition`, `job-unresolved`, `job-continues`, `job-stream`, `running-count`,
  `observation-drops`, 그리고 `LogViewer`가 prop으로 받는 `testid`
- 로그 줄: `data-log-node`, `data-log-time`. `[data-log-time] .log-text`에 로그 원문이 그대로 들어간다
  (하이라이트는 감싸기만 하고 글자를 바꾸지 않는다)
- 노드 선택은 접근 가능한 이름이 "로그 노드"인 `<select>`다
- 상태 배지는 한국어 라벨 옆에 엔진 코드를 그대로 둔다. 테스트 정규식이 코드를 찾는다

### 로그 API

- `q`는 200자까지다(`webLogSearchMaxLen`). 넘으면 400이다. 모르는 `level`도 400이다.
- 커서 형식은 `index-from-to[-fingerprint]`다. 필터를 건 커서는 필터 지문을 담고, 다른 필터로
  쓰면 거절된다. 필터가 없는 커서는 예전 세 부분 형식 그대로다.
- go-wemix의 `EROR`·`DBUG`·`TRCE`와 geth의 `ERROR`·`DEBUG`·`TRACE`는 같은 레벨로 읽는다.
- 명세는 [`web-ui.openapi.yaml`](web-ui.openapi.yaml)의 로그 연산에 있다.

### 세션 기록

- `status.json`과 세션 테스트 목록의 `startedAt`·`finishedAt`은 RFC 3339 UTC다.
  판정이 없는 테스트는 `finishedAt`이 없다. 명세는 [기능 명세](chainbench-feature-spec.md)에 있다.

## 5. 이번에 비싸게 배운 것

- **큰 숫자는 JSON 파서를 지나면 깨진다.** 공용 `webApi`는 응답을 파싱해서 돌려준다. 기록
  요약처럼 큰 정수가 있는 응답은 원문 텍스트를 받아 `parseHistoryJSON`(`web/src/history-json.js`)으로
  읽는다. 작업 상세가 처음에 이 문제로 값을 잃었다.
- **공백 구간에 마지막 값을 보이지 않는다.** 차트 커서가 수집 공백 안에서 직전 값을 보여
  "멀쩡한 노드"로 읽혔다. 가장 가까운 표본을 찾을 때 거리 상한을 두고, 넘으면 "—"를 보인다.
- **CSS 클래스 이름이 판정 이름과 겹친다.** 접근성용 `.skip` 링크가 판정 `skip` 막대와 충돌해
  막대 폭이 틀렸다. 링크는 `.skip-link`로 바꿨다. 판정·상태 이름을 클래스로 쓸 때 공용 클래스와
  겹치는지 본다.
- **기본 노드는 실패한 노드여야 한다.** 처음엔 로그가 알파벳순 첫 노드로 열려 원인과 무관한
  로그를 보여 줬다. 실패한 단언의 노드를 먼저 고른다.
- **대시보드를 다시 띄우면 쿠키가 무효다.** 계정 없는 로컬 모드의 쿠키는 서버가 다시 뜨면
  쓸 수 없다. 화면 확인 중 401이 나오면 대시보드 주소를 먼저 열어 쿠키를 새로 받는다.
- **남은 체인이 `make check`를 깨뜨린다.** 이전 실험의 체인이 포트를 쥐고 있어 테스트 14개가
  실패한 적이 있다. `make check`가 포트 충돌로 실패하면 남은 체인 프로세스부터 확인한다.
- **SPA는 커밋 대상이다.** `npm --prefix web run build`가 `internal/dashboard/spa/`를 다시 만들고,
  Go 바이너리가 그것을 내장한다. Svelte를 고친 뒤 빌드를 빼먹으면 화면이 옛것으로 남는다.
  디자인 토큰 검사(`tests/webui/design_tokens.test.mjs`)는 컴포넌트 안의 hex 색을 거절한다.

## 6. 화면을 확인하는 방법

1. `npm --prefix web run build`로 SPA를 만들고 `go build ./cmd/chainbench-dashboard`로 다시 빌드한다.
2. 대시보드를 `-deployment-root`에 시험용 디렉터리를 주고 띄운다. 실데이터가 없으면 그 아래에
   네트워크 기록을 합성한다. 합성 기록은 `formatVersion` 3, 0보다 큰 `pid`, `logPath`가 있어야
   모니터가 읽는다.
3. chrome-devtools MCP로 데스크톱 폭과 휴대폰 폭을 본다. 스크린샷은 gitignore된 출력
   디렉터리에 둔다.
4. `node --test tests/webui/*.test.mjs`로 화면 로직 단위 테스트를 돌린다.
5. 커밋 전에 `gofmt -l cmd internal tests`와 `make check`를 돌린다.
