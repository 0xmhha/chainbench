## 2. 다음 작업 — NM2 부터

### NM2: Peering 파생 + StaticNodes (다음 착수)

- `netmap` 에 피어링 정책: `mesh`(기본) | `proxied`(bp↔pn↔en, en 은 bp 를 모른다).
- `StaticNodes(label, pubkeyOf func(NodeLabel)(string,bool)) []enode` — 공개키는 **주입**
  (netmap 은 keyring 을 import 하지 않는다).
- 역할 허용은 **기존 seam** `SupportsRole(Role) bool` 로: poa 에 pn 선언 시 오류.
  포트 요구는 `PortReservation() portplan.Reservation` — 새 타입(PortProfile류) 금지.
- **게이트**: mesh 가 현행 4개 조립 지점의 출력과 **바이트 동일**(골든 비교).
  proxied 에서 en 의 목록에 bp enode 가 없을 것.

### NM3: 소비 전환 (주의 최다)

- engine·netcompose 의 static-nodes 조립 → `netmap.StaticNodes` 호출로. **라이브 재검증
  필수**(stablenet·wbft `net up` + api 스펙 — §1f 절차).
- **legacy 역할 값 뒤집기가 여기다**: `LegacySpelling` 삭제, `topology.NodeRole()`·
  `Counts()`·`nodeconfig`·`launchopt` 비교를 canonical 로. argv·영속값이 바뀐다.
- `place` 2모드를 `Assign` 특수형으로 흡수. `netmap.Ports` alias → 실타입 이동(NM-b).
- upgrade·chainsetup 의 조립 2곳은 **F4·F5 와 함께**(A4b 와 동일 근거).

### NM4·NM5: 표면과 영속

- `net allocate` 산출 = netmap (etcd 포함 출력, `--peering`). CLI/MCP 동일 — K8 선례.
- 라벨을 워크스페이스에 영속, 로그 host:port 역추적.

### 그 뒤 (§1g 잔여 — NM 완료 시 N0·N0b·N7 닫힘)

B(DSL 분할 2) · F(패밀리 기동 6 — **A4b 포함**) · N 잔여(청사진 N1~N6, N10~N14) · S(표면 7).
권장 순서: NM 완결 → N1·N2(청사진; netmap 을 산출 타입으로) → F4·F5(wemix, A4b 동반) → S.

## 3. 잊기 쉬운 컨텍스트

- **`LegacySpelling` 은 이행기 장치다** — NM3 에서 삭제. 그 전까지 영속값·argv 는 legacy
  철자("validator"/"endpoint")를 유지한다.
- **`netmap.Ports` 는 `portplan.Ports` 의 alias** — `node.Endpoints`(fan-in 25, etcd 없음)
  교체는 NM3. (NM-b 단계안)
- **etcd 는 모든 패밀리에서 예약** — wbft 배치의 wemix 재사용 안전성.
- 인벤토리 v1/v2 혼용은 거부. v1 은 기존 Placement/Fleet 경로로만.
- **A2 는 허용목록이자 stale 검출** — 파일 쓰기를 없앤 패키지는 layers.md §5 표에서도
  지워야 통과한다. 새로 파일을 쓰면 표에 올리고 판정(✅/◐/❌)을 달아야 한다.
- **A1 은 layers.md §3 표를 파싱** — 새 패키지는 표에 등재해야 통과. `cmd/` 는 대상 외.
- 정리 대기(사용자 확인 필요): 로컬 브랜치 `pr/a~d`·`refactor/core-target`·구 feature
  브랜치들 · 태그 `backup/pre-rebase-20260820`.
