# Web UI 현황과 남은 작업 (2026-10-29)

Web UI 리뉴얼은 화면보다 데이터 목록, 모델, 수집 구조를 먼저 정하는 순서로 진행했고, 화면 단계와 인수 확인까지 끝났다. 그 계획 문서(`web-data-model-plan.md`)는 일이 끝나 지웠고, 지금도 지키는 원칙은 아래 7절로 옮겼다. 이 문서는 무엇이 끝났는지, 무엇을 확인하지 못했는지, 다음에 무엇을 정해야 하는지를 한곳에 모은다. 화면 규칙은 [web/DESIGN.md](../../web/DESIGN.md), 사용자와 사용 장면은 [web/PRODUCT.md](../../web/PRODUCT.md), API 계약은 [web-ui.openapi.yaml](web-ui.openapi.yaml)이 정본이다.

## 1. 끝난 것

### 인수 확인

WEB-01~14 전체 capture를 `72a7b464`(#500 머지 뒤)에서 돌려 14개 모두 통과했다. 그 과정에서 두 가지를 고쳤다.

## 2. 정해야 할 것

1. **WEB-01~14 전체 재capture.** 마지막 전체 capture(`72a7b464`) 뒤에 화면 PR 여섯 개와 API 하나(#503~#509)가 들어가, 지금 main의 인수 증거는 그 시점의 것이다. 기존 결정은 "리뉴얼 뒤 한 번만"이었다. 다시 하면 약 4시간이 걸리고 메모리 여유가 필요하다. WEB-14에는 위 세 고정 커밋의 바이너리를 넘긴다.
2. **wemix 노드가 늦게 내려가는 문제.** #509 확인 중, 다시 실행이 막 띄운 wemix node2(`gwemix`)가 종료 신호를 받고 10초 넘게 남아 개발 증명의 runtime 정리가 거절됐다(노드는 나중에 스스로 내려갔다). gwemix의 시작 직후 종료 처리 때문인지, 정리 대기 시간(10초)이 짧은 것인지 확인하지 않았다. 지금은 `tests/webui/browser_test_jobs.mjs`가 첫 체인(wbft)에서만 다시 실행한다.

## 3. 확인하지 못한 것

- 노드에 실제 이상이 있어 헤드라인에 원이 그려지는 경우(#503)는 단위 테스트로만 확인했다. 녹화 표본(`tests/webui/fixtures/stablenet-sample`)에 그런 실행이 없다.
- 오류 단축키(#508)는 표본에 ERROR 로그가 없어, 확인용 서버가 넣은 ERROR 두 줄로만 확인했다.
- 다시 실행 화면(#509)은 개발 증명의 단언으로만 확인했고, 1440px와 390px에서 직접 띄워 보지 않았다.
- 44px 점검(#504)에서 체인·테스트·설정 화면은 데이터가 거의 없는 표본 상태로만 봤다.
- `tests/webui/browser_history_web09.mjs`는 기록 목록에서 실행 이름으로 찾은 첫 행을 누른다. 작업 기록 행과 세션 기록 행이 같은 이름을 쓰므로 작업 기록 행이 먼저 잡힐 수 있다.

## 4. 기록해 둘 사실

- WEB-14에 넘기는 고정 커밋 바이너리는 예전 기록과 checksum이 다르고, 버전 출력에 커밋 날짜 줄이 없다. 이번 테스트는 그 줄을 요구하지 않았다.
- 첫 capture에서 WEB-13이 한 번 SSH 자격증명 교체 계획 요청 30초 시간 초과로 실패했다. 원인은 모르고, 그 뒤 두 번의 capture에서는 다시 나지 않았다.
- WEB-14 로그의 `Unknown config environment variable envvar=GWEMIX_BIN` 경고는 geth의 환경변수 검사가 내는 것으로 보이지만 확인하지 않았다.

## 7. 지금도 지키는 원칙

2026-10-25에 정한 것 가운데 계속 지키는 것이다.

1. **계약의 원본은 Go 응답 구조체다.** OpenAPI는 손으로 고치되, Go 구조체와 OpenAPI 스키마가 다르거나 서버가 연 경로가 OpenAPI에 없으면 테스트(`TestWebOpenAPIMatchesGoResponses`, `TestWebOpenAPIListsEveryServedRoute`)가 실패한다.
2. **화면은 API 경계에서 응답 모양을 확인한다.** `web/src/api-decode.mjs`의 해독 함수가 그 일을 한다.
3. **실시간 전달은 `/api/v1/events` SSE 하나로 모은다.** 끊기면 스냅숏으로 다시 맞춘다.
4. **Web에서 여는 CLI 인자는 구현이 실제로 읽는 것만이다.** 노드 구성은 체인 preset 계약으로 표현한다.
5. **실패 증거는 비밀 검사를 거친 뒤 Web 기록에 넣는다.**
6. **새 진입점은 기존 기능을 덧붙이는 방식으로 만든다.** 마우스로 설정하고 실행하는 기존 흐름은 그대로 두고, 새 API는 기존 계획·실행 함수를 부른다(#509).
7. **WEB-01~14 전체 capture는 큰 변경을 마친 뒤 한 번만 한다.** WEB-14만 약 3시간이 걸린다. 그 전에는 바꾼 기능의 개발 증명만 골라 돌린다.
