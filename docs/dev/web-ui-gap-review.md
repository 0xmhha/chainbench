# Web UI 계획 대비 누락 검토

상태 정본은 [누락 목록](web-ui-gaps.json)이고, 이 문서는 그 목록을 왜 만들었고 어떻게
닫는지 설명한다. 열네 인수 기준이 모두 통과한 뒤에도 승인된 Seed, 동작 명세, OpenAPI,
화면 디자인에 적힌 내용 가운데 코드가 하지 않는 것이 남아 있었다. 인수 검증은 자기
시나리오만 확인하므로, 통과가 곧 계획 전체의 구현을 뜻하지 않는다.

## 어떻게 찾았는가

2026-10-11 커밋 `ecd01797`에서 여섯 영역을 나누어 문서와 코드를 대조했다. 영역은
인증과 권한, 화면 흐름, 엔진 계약, OpenAPI와 서버 경로, 작업 생명주기, 모니터링과
히스토리다. 파일을 읽고 검색했으며 실행은 하지 않았다. 주요 주장은 코드에서 다시 확인했다.
각 항목의 `code`가 그 근거 위치다.

## 어떻게 닫는가

항목마다 `completion`이 완료 판정 기준이다. 그 기준을 확인하는 테스트가 먼저 실패하고
구현 뒤 통과해야 하며, 확인 명령과 커밋을 적어야 `closed`로 바꿀 수 있다.
`internal/arch/web_gaps_test.go`는 열린 항목이 가리키는 인수 기준을 `complete`로 표시하지
못하게 막는다. 모든 항목을 닫은 뒤에는 고정 소스로 열네 기준을 다시 모두 돌려야 기준을 완료로
바꾼다.

## 1. 승인된 Seed와 어긋나는 것

Seed constraints가 직접 요구하는데 제품 코드에 없는 것이다. 가장 큰 것은 ChainSurface다.
체인 분석 자료와 선택한 바이너리를 대조하는 일을 지금은 인수 준비 스크립트
`tests/webui/fixtures/prepare_web01.py`가 하고 있어서, WEB-01 통과가 이 요구를 증명하지 못했다.

- G-A01은 ChainSurface 카탈로그와 조회 경로를 만든다.
- G-A02는 계획에 ChainSurface 지문을 고정하고 실행 전에 다시 확인한다.
- G-A03은 문서 커밋과 바이너리 커밋을 비교해 stale을 판정하고, help로 매핑을 확인한다.
- G-A04는 실행 옵션 schema에 허용값·범위·기본값을 담는다.
- G-A05는 노드를 여러 서버에 나누어 배치한다.
- G-A06은 G-A05를 구현하며 추가했다. 여러 서버에 나뉜 네트워크의 노드 제어·테스트·로그 수집·관측은 대상 하나를 전제로 한 코드라 지금은 거절한다.

## 2. 명세와 OpenAPI에서 빠진 것

OpenAPI 51개 operation 가운데 네 개는 서버 경로가 없었고, 서버에는 문서에 없는 경로가
25개 있었다. 동작 명세가 정한 상태 전이와 오류 형식도 일부 다르다.

- G-B01은 계약 ID 조회, G-B02는 workspace의 network 조회, G-B03은 감사 기록의 형식 통일과 조회다.
- G-B04는 서버 경로와 OpenAPI를 같게 맞추고 테스트로 지킨다.
- G-B05는 개인·팀 모드의 바인딩과 TLS 조건을 실제로 강제한다.
- G-B06은 작업 상태 전이를 상태도대로 고친다.
- G-B07은 busy 409에 현재 작업과 실행자를 담는다.
- G-B08은 재시작 뒤 실제 상태를 확인하고 명시적 복구를 제공한다.
- G-B09는 오류 본문을 명세 형식에 맞춘다.
- G-B10은 목록 조회의 cursor와 limit을 지킨다.
- G-B11은 실행 목록 문서를 만든다.
- G-B12는 히스토리 비교와 Run 필드를 채운다.
- G-B13은 관리자 삭제가 실행 소유 세션을 지우게 한다.
- G-B14는 관측 누락 범위와 다운샘플 해상도를 알린다.
- G-B15는 등록된 설정 파일로 교체한다.
- G-B16은 배포의 부분 효과를 노드와 파일 단위로 남긴다.
- G-B17은 계약 버전을 계약 내용에서 만들고 변경 시 다시 검증한다.
- G-B18은 export에 필요한 binding을 적는다.
- G-B19는 Job에 자격증명 참조와 취소 메시지를 남긴다.

## 3. 화면과 디자인 문서에서 빠진 것

동작 명세의 화면 표와 화면 디자인 문서가 정한 화면 가운데 없는 것이 있다.

- G-C01은 노드 상세, G-C02는 작업 상세, G-C03은 계획 검토의 접근 권한과 차이 표시다.
- G-C04는 차트의 빈 구간 처리와 시간·노드·metric 선택이다.
- G-C05는 Settings의 자격증명·사용자·감사 화면이다.
- G-C06은 상단 바와 화면 사이의 선택 공유다.
- G-C07은 대시보드의 실행 중 작업과 관측 누락 요약이다.
- G-C08은 DSL 편집기의 트리와 오류 이동이다.
- G-C09는 필드에 연결된 오류와 키보드 검증이다.
- G-C10은 프론트에 적은 선택지를 계약에서 받는 일이다.
- G-C11은 한국어 문구, 예전 로그인 폼 제거, 색 토큰과 상태 아이콘이다.
- G-C12는 모니터링 화면의 선택과 취소다.
- G-C13은 체인 구성 상세에 선택 바이너리의 ChainSurface를 보이는 일이다(G-A01 구현 중 추가).

## 4. 결함

- G-D01은 리비전 복사 누락이다.
- G-D02는 없는 경로의 권한 규칙이다.
- G-D03은 역할 변경과 철회가 원자적이지 않은 문제다.
- G-D04는 `-deployment-accounts` 모드가 보안 계층을 건너뛰고, WEB-03과 WEB-04 인수 검증이
  그 모드로 서버를 띄우는 문제다.
- G-D05는 README 예시가 지금 기본값에서 실패하는 문제다.
- G-D06은 구현 상태 문서가 코드보다 뒤처진 문제다.
- G-D07은 G-A01을 실제 바이너리로 확인하다 찾았다. 숨김 플래그를 `<flag> --help`로 물으면 값을 받는 플래그가
  `--help`를 값으로 삼아 사용자 기본 데이터 디렉터리에서 노드를 띄운다. 2026-10-11 15:13~15:14 확인 중
  `~/Library/Ethereum/gstable`·`gwemix`가 생겼고, 지우지 않고 `/private/tmp/chainbench-probe-leftovers-20261011`로 옮겼다.
- G-D08은 같은 확인에서 찾았다. 신원 검사가 서버 환경을 물려줘 `GWEMIX_*` 변수 하나로 version 첫 줄이 바뀐다.

## 진행 순서

Seed 묶음을 먼저 닫고, 다음으로 명세 묶음, 화면 묶음 순서로 진행한다. 결함은 같은 파일을
고치는 묶음에서 함께 닫는다. 각 단계는 실패하는 테스트를 먼저 쓰고, 구현하고, 관련 회귀를
돌린 뒤 커밋한다. 모든 항목이 닫히면 열네 기준을 고정 소스로 다시 돌린다.

## 닫은 항목

각 항목의 `evidence`에 RED와 GREEN을 적는다. 인수 기준은 마지막 고정 소스 재실행 전까지 열린 채로 둔다.

- `4b524de7`에서 G-A01, G-A03, G-A04, G-D07, G-D08을 닫았다. 세 실제 바이너리가 모두 `verified`로 판정됐다.
  G-A02는 계획 고정과 실행 전 재확인을 단위 테스트로 확인했지만, 실제 계획 응답에서 확인하기 전까지 열어 둔다.
- `652f0fa9`에서 G-B01, G-B02, G-B03을 닫았다. 요청마다 다른 requestId가 응답과 감사 기록에 남으며, 이는 G-B09의 일부다.
- `a37327c4`에서 G-C10을 닫았다. 작업 종류는 jobs 계약, 역할과 자격증명 종류는 access 계약(`0285ba2a`), 노드 역할과 동기화 방식은 체인 프리셋 계약에서 받는다. 브라우저로 화면을 연 확인은 인수 재실행에서 한다.
- `45b2a68e`에서 G-C02, G-C06, G-C07을 닫았다. 실제 wbft 네트워크로 브라우저 증명(`run_navigation.py`)을 돌렸다. G-C12는 모니터링에 네트워크 선택과 취소를 붙였지만 증명이 그 화면에서 고르거나 취소하지 않았으므로 열어 둔다.
- 같은 증명에서 결함 둘을 찾아 고쳤다. G-D09(`f248fef8`)는 help 검사 지문이 호출마다 달라 검토한 계획을 시작하지 못하던 문제로, `4b524de7`의 격리 검사에서 생겼다. G-D10(`2df3278e`)은 정리에 성공한 작업이 이미 지운 자원을 계속 보이던 문제다.
- `78f1a91d`, `7db313cd`에서 G-C01, G-C03, G-C13을 닫고 G-A02도 닫았다. 실제 wbft 노드로 브라우저 증명(`run_node_detail.py`)을 돌렸다. G-A02는 실제 계획 응답에 고정된 surface가 담기는 것을 확인했고, 계획과 시작 사이에 surface가 바뀌는 경우는 단위 테스트로만 확인했다.
- `a65e6432`에서 G-C04, G-C12를 닫았다. 실제 wbft 노드 하나를 20초 멈춰 차트 선이 끊기는 것을 확인했고, 멈추지 않은 노드는 한 선으로 그려지는 것도 함께 확인했다.
- `1304fe56`, `0e7e3eb8`에서 G-C08을 닫았다. G-C09는 DSL 편집기에서 완료 조건(aria-invalid, 요약에서 필드로 포커스, 키보드만으로 저장과 작업 취소)을 브라우저로 확인했지만, 배포 문서와 체인 프리셋 편집기는 아직 오류를 상태 줄로만 보이므로 열어 둔다.
- `ddc70fe7`, `d85eb753`에서 G-C09, G-C11을 닫았다. 배포 문서와 체인 프리셋 편집기도 잘못된 필드를 표시하고 요약에서 그 필드로 이동한다. 색은 토큰만 쓰고, 상태는 아이콘과 낱말을 함께 보인다.
- `107e3129`에서 G-B04를 닫았다. 서버 경로와 OpenAPI가 어긋나면 arch 테스트가 실패한다.
