# 공통 테스트 분리 변경 범위

> 출처: Confluence [공통 테스트 분리 변경 범위](https://wemade.atlassian.net/wiki/spaces/platfomDev/pages/2987720853) (페이지 ID 2987720853, 버전 3, 최종 수정 2026-09-11)  
> 상위 페이지: [Common] Test  
> 가져온 날짜: 2026-09-18 (본문은 Confluence markdown 변환 결과를 그대로 옮김)

---

공통 테스트 70개를 세 체인에서 같은 뜻으로 돌리기 위해 바꿀 것을 순서대로 적는다. 앞 단계 없이 뒤 단계를 하면 테스트 수는 늘어도 세 체인에서 같은 뜻으로 돌지 않는다. 노드 프로그램 소스를 바꿔 기능을 맞추는 일은 범위에 없다.

| 순서 | 작업 | 바뀌는 곳 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 테스트 ID 고정 | 공통 테스트 목록, 결과 기록 | 70개 CT ID와 기존 ID 대응이 결과 기록에 남는다 |
| 2 | 체인별 환경 세 벌과 공통 테스트 분리 | 자동 테스트의 환경 선언, 적용 체인 목록 | 같은 테스트 파일이 세 환경으로 각각 돈다. WEMIX4.0 프로그램 이름 불일치를 고친다 |
| 3 | 고정 주소 제거 | 자동 테스트 35개, 테스트 계정 선언 | 테스트에 고정 주소가 없다(0 주소와 상수 주소 제외) |
| 4 | 절차 상수를 프로필에서 넣는 문법 또는 생성기 | 테스트 문법 또는 생성기 | 수수료, 시간, 기대값 상수가 프로필에서 온다 |
| 5 | 로컬 서명 전송 통합 | 실행 도구의 전송 경로 | 계약 생성, 데이터, 가스, nonce, 수수료, 접근 목록, 대납 형식이 로컬 서명으로도 같은 결과를 낸다. 자금 지급, 배포, 부하 전송이 이를 같이 쓴다 |
| 6 | 체인별 정답 계산과 팁 출처 치환 | 계산 규칙, 체인 설정 | 헤더 팁을 읽는 자동 테스트 12개가 체인 무관 입력으로 바뀐다. 기본 수수료, 최소 수수료, 장애 허용 수 정답이 프로필에서 온다 |
| 7 | 거부 사유 문구 표와 판정 강화 | 거부 판정, 테스트의 사유 항목 | 이유가 틀린 거부가 통과하지 않는다 |
| 8 | 기능 사전 확인과 건너뜀 이유 기록 | 기능 확인, 체인 설정 | 계정 코드 위임, P256, 합의 API, 계정 상태 기능이 실제 노드 값으로 판정된다 |
| 9 | 외부 주소 프로필 | 외부 주소 연결, 노드 표 | 공개 RPC에서 노드 역할, 웹소켓, 지표가 프로필대로 동작한다 |
| 10 | 세 체인 일괄 실행과 결과 기록 | 결과 기록, 보고서 | 세 체인 결과가 같은 CT ID로 묶이고 프로그램 해시, 체인 ID, 하드포크 상태, 서명 방식이 남는다 |
| 11 | 회귀 실행 묶음과 준비물 공유 | 실행 순서 목록, 파일 사이 값 전달 | 묶음 A\~E가 네트워크 하나에서 순서대로 돌고, 배포 주소와 영수증을 뒤 파일이 이름으로 읽는다. 결과는 CT ID마다 남는다 |

## 이 저장소가 더한 것: 단계별 상태 (2026-10-29)

> 위 본문은 Confluence 를 그대로 옮긴 것이고, 이 절만 chainbench 저장소가 더했다. 공통 테스트는 지금 72개다([공통 테스트 목록](01-common-test-list.md)).
> 근거는 이 날짜의 코드와 [`mainnet-config-worklist.md`](../../dev/architecture/mainnet-config-worklist.md) 의 상태 칸이다. 적지 않은 단계는 이번에 확인하지 않았다.

| 순서 | 지금 상태 |
| --- | --- |
| 3 | 끝났다. 해석기가 닿는 자리의 계정 주소 35곳을 라벨로 바꿨고(H3, 2026-09-15), 남은 14곳도 바꿨다(H3-b, 2026-09-18). |
| 5 | 코드 경로는 끝났다. 로컬 서명이 legacy, 접근 목록, 동적 수수료, 대납 형식에서 데이터, 가스, nonce, 수수료, 접근 목록을 담고, 계약 생성은 `deployContract` 가 같은 형식들로 보낸다. 자금 지급(`faucet`), 배포, 부하 전송(`load`)이 같은 경로를 쓴다. 다만 R4 는 다른 포크와 제어 입력 조합, 전수 회귀가 남았다며 "부분 완료" 로 둔다. 그래서 완료 기준의 "같은 결과를 낸다" 는 아직 전부 검증되지 않았다. |
| 7 | 일부 끝났다. 거부는 사유 문구로 판정하고 `rpcError` 검사가 있다([별도 구현이 필요한 항목](03-separate-implementation-items.md) §2). R5 는 제출 분류를 "부분 완료" 로 둔다. |
| 8 | 일부 끝났다. 합의 API, PUSH0, P256 등을 실제 노드에서 확인한 뒤 건너뜀을 판정한다. 계약 ABI, 버전, 권한과 계정 상태 확인은 남았다(R3). |
| 9 | 읽기 쪽은 끝났다. `chain-preset.attach.endpoints` 가 역할, 웹소켓, 지표 주소를 담는다(R2, 2026-10-13). 이 주소로 로컬 서명 거래를 인증해 보내는 일은 R4 에 남아 있다. |
| 10 | 일괄 실행은 끝났다. `run --chain-presets` 와 MCP `chainPresets` 가 대상마다 돌리고 preset ID 를 결과에 남긴다(R6, 2026-10-14). 프로그램 해시, 하드포크 상태, 서명 방식을 같이 남기는 일은 R6 에 들어 있지 않다. |
| 11 | 준비물 공유는 끝났다. `prepared.exports` 와 `prepared.imports` 로 배포 주소와 영수증을 뒤 파일이 이름으로 읽는다(2026-10-20). 묶음 A~E 를 실행 순서 목록으로 만든 파일은 `tests/tc` 에 없다. |
