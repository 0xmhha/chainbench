## 테스트와 결과

| 용어 | 뜻 |
| --- | --- |
| 공통 테스트 | WEMIX3.0, WEMIX4.0, StableNet 세 체인에서 같은 목적으로 실행할 수 있는 테스트. ID는 CT-로 시작한다 |
| 두 체인 테스트 | 세 체인 중 두 체인에서만 같은 목적으로 실행할 수 있는 테스트. 새 ID를 주지 않고 기존 ID로 부른다 |
| 기존 ID | Confluence 명세에 이미 있는 테스트 번호. RT-(StableNet 회귀), TC-와 TS-(StableNet 1차 변경), NODE-, TX-, WBFT-, RPC-(WEMIX4.0), ETCD-, MINING-, BRIOCHE-(WEMIX3.0), T-(2차 변경), N-(PR196 신규) |
| 자동 테스트 | 실행 도구(chainbench)에 파일로 정의된 테스트. 실행 이름(예: nonce-ordering)으로 부른다 |
| PR196 관리 번호 | WEMIX3.0 PR196 회귀 문서가 명세 번호 없는 자동 테스트에 붙인 번호(PR196-TC-001부터) |
| 부분 대응 | 기존 명세의 일부만 세 체인 공통이라는 뜻. 명세 그대로는 한두 체인에만 해당한다 |
| 프로필 | 체인 하나를 돌릴 때 쓰는 값 묶음. 계정, 주소, 체인 ID, 하드포크, 수수료, 노드 구성, 프로그램 경로가 들어간다 |
| 설정으로 분리 | 테스트 절차는 그대로 두고 값만 프로필로 빼면 되는 경우 |
| 기대값은 체인별 계산 | 같은 입력에서 나와야 할 정답이 체인마다 달라 정답을 따로 구해야 하는 경우 |
| 별도 구현 필요 | 실행 도구에 없는 기능을 만들거나, 노드를 직접 다뤄야 하는 경우 |
| 건너뜀 | 체인에 그 기능이 없거나 실행 조건이 안 맞아 테스트를 돌리지 않은 것. 통과가 아니다 |

## 체인과 노드

| 용어 | 뜻 |
| --- | --- |
| WEMIX3.0 | go-wemix 노드 프로그램으로 운영하는 체인. 합의는 etcd 기반 PoA |
| WEMIX4.0 | go-wbft 노드 프로그램으로 운영하는 체인. 합의는 WBFT. 하드포크 전 구간은 WEMIX3.0 방식 |
| StableNet | go-stablenet 노드 프로그램으로 운영하는 체인. 합의는 WBFT |
| 생성 노드 | 블록을 만드는 노드. 검증자 노드라고도 한다 |
| 종단 노드 | 블록을 만들지 않고 동기화와 조회만 하는 노드 |
| 전달 노드 | 생성 노드와 종단 노드 사이에서 블록을 전달하는 노드. 부트노드 역할을 겸한다 |
| 제네시스 | 블록 0을 만드는 설정 파일. 체인 ID, 하드포크 높이, 초기 계정 잔액, 시스템 컨트랙트가 들어간다 |
| 하드포크 | 정해진 높이나 설정에 따라 규칙이 바뀌는 지점. WEMIX는 Pangyo, Applepie, Brioche, Croissant, StableNet은 Anzeon, Boho |
| 우리가 띄운 네트워크 | 실행 도구가 직접 노드를 띄워 제어하는 네트워크. 노드 계정 서명과 장애 주입이 된다 |
| 공개 RPC | 이미 운영 중인 네트워크의 조회 주소. 노드 계정 서명과 장애 주입이 안 된다 |

## 트랜잭션과 수수료

| 용어 | 뜻 |
| --- | --- |
| Legacy 형식 | gasPrice 하나로 수수료를 정하는 예전 트랜잭션 형식(0x0) |
| 접근 목록 형식 | 미리 접근할 주소와 저장 위치를 적는 형식(0x1) |
| 동적 수수료 형식 | 최대 수수료와 팁을 따로 정하는 형식(0x2) |
| 수수료 대납 형식 | 보내는 계정과 수수료 내는 계정이 다른 형식(0x16). 세 체인 모두 지원 |
| 계정 코드 위임 | 일반 계정에 컨트랙트 코드를 위임하는 형식(0x4, EIP-7702). WEMIX3.0은 지원하지 않는다 |
| 기본 수수료 | 블록마다 정해지는 최소 가스 가격. 변화 규칙이 체인마다 다르다 |
| 팁 | 기본 수수료 위에 얹는 우선 수수료. StableNet 일반 계정은 블록 헤더 값으로 바뀐다 |
| 실제 적용 가스 가격 | 영수증에 기록되는, 실제로 낸 가스 단가 |
| 최소 수수료 | 이보다 낮으면 노드가 받지 않는 수수료. 기준이 체인마다 다르다 |
| 거부 | 트랜잭션이 블록에 들어가기 전에 노드가 받지 않는 것 |
| 실행 실패 | 블록에는 들어갔지만 실행이 되돌려지거나 가스가 바닥난 것. 영수증 상태가 실패다 |
| nonce | 계정이 보낸 트랜잭션의 순번. 순서대로만 처리된다 |
| 교체 | 같은 nonce에 수수료를 올려 다시 보내 앞의 트랜잭션을 밀어내는 것 |

## 컨트랙트

| 용어 | 뜻 |
| --- | --- |
| 일반 컨트랙트 | 테스트가 직접 배포하는 컨트랙트. 세 체인 공통 |
| 시스템 컨트랙트 | 체인이 제네시스에 넣어 두는 컨트랙트. 주소, 함수, 뜻이 체인마다 다르다 |
| 조회 호출 | 트랜잭션 없이 컨트랙트 값을 읽는 호출(eth\_call) |
| 되돌림 | 컨트랙트 실행이 조건에 걸려 취소되는 것(revert) |
| 가스 소진 | 가스 한도가 모자라 실행이 실패하는 것 |
| 프리컴파일 | 노드에 내장된 특수 컨트랙트. P256 서명 검증(0x100)은 WEMIX3.0에 없다 |

## 조회와 동기화

| 용어 | 뜻 |
| --- | --- |
| RPC | 노드에 요청을 보내는 인터페이스. HTTP와 웹소켓이 있다 |
| API 묶음 | eth, net, web3, txpool, admin처럼 이름으로 묶인 기능. 기본으로 열리는 것은 net, web3뿐이다 |
| 합의 정보 API | 검증자 목록, 서명자, 합의 상태를 조회하는 API(istanbul\_). WEMIX4.0과 StableNet에만 있다 |
| 웹소켓 구독 | 새 블록이나 이벤트를 실시간으로 받는 연결 |
| 트랜잭션 풀 | 블록에 들어가기 전 트랜잭션이 대기하는 곳. 대기(pending)와 보류(queued)로 나뉜다 |
| Full 동기화 | 모든 블록을 실행하며 따라잡는 동기화 |
| Snap 동기화 | 상태 스냅샷을 받아 빠르게 따라잡는 동기화 |
| 지표 | 노드가 내놓는 상태 수치(metrics). 최신 블록 높이 등 |
