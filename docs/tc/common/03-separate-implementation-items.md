> 출처: Confluence [별도 구현이 필요한 항목](https://wemade.atlassian.net/wiki/spaces/platfomDev/pages/2987884735) (페이지 ID 2987884735, 버전 3, 최종 수정 2026-09-11)  
> 상위 페이지: [Common] Test  
> 가져온 날짜: 2026-09-18 (본문은 Confluence markdown 변환 결과를 그대로 옮김)

---

값을 바꿔도 같은 입력에서 나와야 할 정답이 체인마다 다르거나, 실행 도구에 필요한 기능이 없는 항목이다. 두 부류로 나눈다. "체인별 정답 계산"은 공통 절차를 두고 정답만 체인별로 구하는 것이고, "도구 기능 추가"는 실행 도구에 없는 경로를 만드는 것이다.

## 1. 체인별 정답 계산이 필요한 것

| 항목 | 세 체인이 같이 쓰는 부분 | 체인별로 다른 부분 | 해당 테스트 |
| --- | --- | --- | --- |
| 수수료 규칙 | 트랜잭션, 영수증, 블록 헤더를 읽어 금액을 비교하는 절차 | 기본 수수료 변화식과 상한·하한, 최소 팁과 최소 수수료 기준, 실제 적용 가스 가격(StableNet 일반 계정은 헤더 팁으로 바뀜), 대납자 잔액 검사 기준 | CT-FEE-001, CT-FEE-002, CT-FEE-010, CT-TX-002, CT-TX-003, CT-TX-005, CT-TX-008 |
| 수수료 입력 출처 | 기본 수수료에 팁을 더해 최대 수수료를 만드는 절차 | 팁을 어디서 읽는지. StableNet은 블록 헤더, WEMIX3.0은 거버넌스 제안값, WEMIX4.0은 최근 블록 표본 | 헤더 팁을 읽는 자동 테스트 12개 |
| 거부 사유 판정 | 거부됐는지 확인하는 절차 | 사유 문구 뒤에 붙는 설명. 앞부분 문구로 판정하고 체인별 문구 표를 둔다 | CT-TX-006\~008, CT-TX-015, CT-TX-016, CT-FEE-001, CT-FEE-002 |
| 합의 정상·장애 판정 | 블록 진행, 같은 높이 해시 일치, 피어 수 관찰 | 검증자 조회 방법, 허용되는 장애 수(WBFT는 3분의 2 이상 생존, WEMIX3.0은 etcd 과반), 블록 주기, 에폭 | CT-NODE-001, CT-NODE-011, CT-NODE-016, CT-FAULT-001\~006 |
| 컨트랙트 코드 | 배포와 호출 절차 | 코드가 요구하는 EVM 버전. WEMIX3.0은 최신 명령어(PUSH0 등)를 켜지 않는다. 공통 테스트는 PUSH0 없이 손으로 쓴 바이트코드를 써서 세 체인에서 같게 돈다 | CT-CONTRACT-001\~007, CT-TX-014, CT-TX-017, CT-RPC-009, CT-RPC-014 |
| 계정 준비 | 계정 생성, 자금 지급, nonce 분리 | StableNet에서 차단·인증 상태가 아닌지 미리 확인 | 계정을 쓰는 모든 테스트 |
| 제네시스 준비 | 환경 선언 | WEMIX3.0은 노드 프로그램이 거버넌스 설정에서 제네시스를 만들고, 나머지는 템플릿에 값을 채운다. 기대 제네시스 해시는 체인별 | CT-NODE-003 |
| 동기화 관찰 | 동기화 상태, 높이 따라잡기 | 기본 동기화 방식(WEMIX3.0은 snap, 나머지는 full)은 실행 도구가 설정에 적어 드러나지 않는다. WEMIX3.0의 생성 노드 간 동기화 점검이 끼어들지 않게 생산하지 않는 노드에서 관찰한다 | CT-NODE-004\~007, CT-FEE-009 |

## 2. 실행 도구에 추가해야 하는 것

| 기능 | 지금 상태 | 필요한 것 | 해당 테스트 |
| --- | --- | --- | --- |
| 로컬 서명 전송 | 코드 경로는 해결(2026-10-29 코드로 확인). 로컬 키 전송이 legacy, 접근 목록, 동적 수수료, 대납 형식 모두에서 데이터, 가스, nonce, 수수료, 접근 목록 항목을 담는다. 계약 생성은 `deployContract` 가 같은 형식들로 로컬 서명해 보내고, 자금 지급(`faucet`)과 부하 전송(`load`)도 보내는 계정이 로컬 키를 가지면 이 경로를 쓴다. 이 경로가 담지 못하는 조합(대납과 `gasPrice` 등)은 조용히 버리지 않고 거부한다. 검증 범위는 아직 남았다. [mainnet-config-worklist](../../dev/architecture/mainnet-config-worklist.md) R4 는 다른 포크와 제어 입력 조합, 전수 회귀를 남은 일로 적고 상태를 "부분 완료" 로 둔다 | 모든 전송이 로컬 키로도 되게 한다. 계약 생성, 데이터, 가스, nonce, 수수료, 접근 목록, 대납 형식을 한 경로에서 다룬다 | 공개 RPC에서 돌릴 모든 전송 테스트 |
| 기능 사전 확인 | 일부 해결. 합의 API, PUSH0, P256, RPC 접근, 웹소켓 구독, 시스템 컨트랙트 코드를 실제 노드에서 확인한 뒤 `skipsOn` 을 판정한다. 계약 ABI, 버전, 권한, 포크와 그 밖의 RPC, 계정 상태 확인은 남았다(mainnet-config-worklist R3) | 계정 코드 위임, P256, 대납 형식, 합의 API, 계정 상태 기능을 실제 노드에서 확인하고, 없으면 "건너뜀"과 이유를 남긴다 | 형식·API 의존 테스트 전부 |
| 외부 주소 프로필 | 해결(2026-10-13). `chain-preset.attach.endpoints` 가 주소별 역할, RPC, 웹소켓, 지표 주소, 인증 환경변수 참조, 선언한 API 목록을 담는다([endpoint-profiles.md](../../dev/endpoint-profiles.md)). 선언한 API 목록은 실제로 지원한다는 증거가 아니므로 실제 확인은 기능 사전 확인이 맡는다 | 주소별 역할, 웹소켓·지표 주소, 인증 정보, 열린 API를 적는 설정 | CT-RPC-013\~015, 역할을 고르는 테스트 |
| 거부 판정 강화 | 해결(2026-09-29). 전송 거부는 사유 문구 일부 일치로 판정하고, 임의 RPC 호출이 정해진 문구로 실패해야 하는 경우는 `rpcError` 검사로 본다 | - | 거부 테스트 전부, CT-TX-011 |
| 동기화 경로 관찰 | 해결(2026-09-29). 세 클라이언트가 같은 이름으로 내는 지표(`eth_downloader_headers_in`, `eth_downloader_receipts_in`, `eth_fetcher_block_broadcasts_in`)로 본다. 지표 포트가 밖으로 열려 있지 않은 서버에서는 그 서버 안에서 읽는다. snap 동기화에 필요한 "블록을 하나도 갖지 않은 노드" 는 생산하지 않는 노드를 genesis 상태로 되돌려(resetNode) 만든다 | - | CT-NODE-004\~007, CT-FEE-009 |
| 실행 결과 기록 | 일부 해결(2026-10-14). 세 체인 일괄 실행이 결과, session, status, report 에 고른 preset ID 와 케이스가 실제로 쓴 preset ID 를 남긴다. 프로그램 해시와 버전, 하드포크 상태, 서명 방식, 건너뛴 이유를 함께 남기는 일은 R6 에 들어 있지 않다(mainnet-config-worklist §8 대응표). 이 넷이 다른 경로로 결과에 남는지는 다시 확인하지 않았다 | 세 체인 결과를 같은 테스트 ID로 묶고 위 정보를 남긴다 | 전부 |
| 세 체인 일괄 실행 | 해결(2026-10-14). `chainbench run --chain-presets` 를 반복하거나 MCP `chainbench_run` 에 `chainPresets` 를 주면 대상마다 따로 작업 폴더를 두고 차례로 돌린 뒤 JSON `runs` 에 대상별 결과를 모은다([DSL 작성 가이드](../../guide/dsl-authoring.md)) | 세 프로필로 이어 돌리고 결과를 한 표로 모은다 | 전부 |
| 준비물 공유 | 해결(2026-10-20, b9451864). 공급 케이스가 `prepared.exports` 로 공개한 값을 소비 케이스가 `prepared.imports` 로 읽는다. 공급 케이스가 PASS 가 아니면 소비 케이스는 BLOCKED 로 남는다([DSL 작성 가이드](../../guide/dsl-authoring.md)) | 준비 단계가 남긴 값을 뒤 파일이 이름으로 읽는 기능. 회귀 실행 묶음이 이를 전제로 한다 | 묶음 A, C |

## 3. 두 체인에만 있어 공통에서 뺀 기능

합의 정보 API, 블록 헤더의 합의 정보, 계정 코드 위임, P256 서명 검증은 WEMIX4.0과 StableNet에만 있다. Brioche 보상은 WEMIX3.0과 WEMIX4.0에만 있다. 기본 수수료 상한은 WEMIX3.0과 StableNet에만 있다. 이들은 부록 A에 기존 ID로 정리했다. 계정 코드 위임과 P256은 두 체인 사이에서도 켜는 방법이 달라, 지원 여부와 활성 여부를 나눠 확인해야 한다.
