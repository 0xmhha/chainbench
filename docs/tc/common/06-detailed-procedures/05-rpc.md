이 페이지는 조회·구독 API 영역 공통 테스트 15개의 준비, 절차, 기대 결과, 체인별 차이를 적는다. 목록과 ID 규칙은 [공통 테스트 목록](https://wemade.atlassian.net/wiki/spaces/platfomDev/pages/2988965889) 페이지에 있다. 세 체인의 값이 다른 곳은 "체인별 차이"에 적었고, 그 값은 실행 설정(프로필)에 둔다.

## CT-RPC-001 · 최신 블록 번호 조회

- **목적**: 블록 번호가 계속 늘어나는지 확인한다.
- **의존 요소**: RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 일정 간격으로 블록 번호를 여러 번 조회한다.
- **기대 결과**: 이전 값 이상으로 늘어난다.
- **비고**: 기존 명세: RT-A-4-01, RPC-001 / 자동 테스트: basic-rpc-health (PR196-TC-007), remote-rpc-health (PR196-TC-028) / PR196 우선순위: P1/P2

## CT-RPC-002 · 블록 번호로 블록 조회

- **목적**: 최신 블록을 번호로 조회하면 필수 필드가 있는지 확인한다.
- **의존 요소**: RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 최신 블록을 조회한다.
    2. 번호, 해시, 트랜잭션 목록 필드를 확인한다.
- **기대 결과**: 번호와 해시가 16진수이고 트랜잭션 목록 필드가 있다.
- **체인별 차이**: WEMIX4.0 명세는 합의 정보 포함까지 요구한다. 그 부분은 2체인이라 제외했다.
- **비고**: 기존 명세: RT-G-1-01, RPC-002 (부분 대응) / 자동 테스트: block-transactions-field / PR196 우선순위: P1

## CT-RPC-003 · 블록 해시로 블록 조회

- **목적**: 해시로 조회한 블록이 번호로 조회한 블록과 같은지 확인한다.
- **의존 요소**: RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 최신 블록의 해시와 번호를 조회한다.
    2. 해시로 다시 조회해 비교한다.
- **기대 결과**: 해시와 번호가 같다.
- **비고**: 기존 명세: RT-G-1-02, RPC-002 (부분 대응) / 자동 테스트: block-by-hash-consistency / PR196 우선순위: P1

## CT-RPC-004 · 해시로 트랜잭션 조회

- **목적**: 포함된 트랜잭션을 해시로 조회하면 보낸 이, 받는 이, 블록 번호, 금액이 있는지 확인한다.
- **의존 요소**: 테스트 계정, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 송금을 보낸다.
    2. 해시로 트랜잭션을 조회한다.
- **기대 결과**: 보낸 이와 받는 이가 요청값과 같고 블록 번호와 금액이 있다.
- **비고**: 기존 명세: RT-G-1-03 / 자동 테스트: transaction-by-hash-fields / PR196 우선순위: P1/P2

## CT-RPC-005 · 영수증 조회

- **목적**: 영수증에 상태, 실제 적용 가스 가격, 로그가 있는지 확인한다.
- **의존 요소**: 테스트 계정, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 송금을 보낸다.
    2. 영수증을 조회한다.
- **기대 결과**: 상태가 성공이고 가스 가격과 로그 필드가 있다.
- **비고**: 기존 명세: RT-G-1-04, RPC-007 / 자동 테스트: transaction-receipt-fields / PR196 우선순위: P1

## CT-RPC-006 · 계정 nonce 조회

- **목적**: 트랜잭션을 보내면 계정 nonce가 1 늘어나는지 확인한다.
- **의존 요소**: 테스트 계정, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. nonce를 조회한다.
    2. 송금을 보낸다.
    3. nonce를 다시 조회한다.
- **기대 결과**: 1 늘었다.
- **비고**: 기존 명세: RT-G-1-05, RPC-015 / 자동 테스트: transaction-count-increments / PR196 우선순위: P1

## CT-RPC-007 · 잔액 조회

- **목적**: 잔액이 있는 계정의 잔액이 정확히 조회되는지 확인한다.
- **의존 요소**: 테스트 계정, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 알려진 계정의 잔액을 조회한다.
    2. 송금 전후로 다시 조회한다.
- **기대 결과**: 0보다 크고 송금 후 변화가 반영된다.
- **비고**: 기존 명세: RT-A-4-02, RPC-012 / 자동 테스트: genesis-balance, remote-balance-check (PR196-TC-030) / PR196 우선순위: P2

## CT-RPC-008 · 체인 ID 조회

- **목적**: 모든 노드가 제네시스에 설정한 체인 ID를 돌려주는지 확인한다.
- **의존 요소**: 체인 ID, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 각 노드에서 체인 ID를 조회한다.
    2. 설정값과 비교한다.
- **기대 결과**: 모든 노드가 설정값과 같은 값을 돌려준다.
- **체인별 차이**: WEMIX3.0과 WEMIX4.0의 코드 기본값이 같으므로 체인 ID만으로 어느 체인인지 판단하지 않는다.
- **비고**: 기존 명세: RT-A-4-05, RPC-013 / 자동 테스트: chain-id, remote-chain-info (PR196-TC-029) / PR196 우선순위: P2/P3 / 기존 자동 테스트는 0보다 큰지만 보므로 설정값 비교로 바꾼다.

## CT-RPC-009 · 이벤트 로그 조회

- **목적**: 이벤트를 내는 컨트랙트를 실행한 뒤 조건에 맞는 로그가 조회되는지 확인한다.
- **의존 요소**: 테스트 계정, 컨트랙트, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 이벤트를 내는 컨트랙트를 배포하고 호출한다.
    2. 주소와 토픽으로 로그를 조회한다.
- **기대 결과**: 조건에 맞는 로그가 돌아오고 토픽이 예상값과 같다.
- **비고**: 기존 명세: RT-A-4-04, RPC-014 / 자동 테스트: logs-query-well-formed, contract-event-emitted / PR196 우선순위: P1/P2

## CT-RPC-010 · 서명된 트랜잭션 전송과 풀 조회

- **목적**: 직접 서명한 트랜잭션을 보내면 해시가 돌아오고 포함 전에 풀에서 보이는지 확인한다.
- **의존 요소**: 테스트 계정, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 로컬 키로 서명한 트랜잭션을 보낸다.
    2. 포함 전에 풀 내용을 조회한다.
    3. 포함 후 영수증을 조회한다.
- **기대 결과**: 해시가 돌아온다. 풀에서 보였다가 블록에 포함된다.
- **체인별 차이**: 풀 조회는 관리용 API라 공개 RPC에서는 닫혀 있을 수 있다.
- **비고**: 기존 명세: RT-A-4-03 / PR196 우선순위: P1 / 자동 테스트 value-transfer는 전송 부분만 대응.

## CT-RPC-011 · 트랜잭션 풀 건수 조회

- **목적**: 대기 건수와 보류 건수가 넣은 수와 맞는지 확인한다.
- **의존 요소**: 테스트 계정, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 연속 nonce 트랜잭션과 nonce 격차가 있는 트랜잭션을 넣는다.
    2. 풀 건수를 조회한다.
- **기대 결과**: 대기 건수와 보류 건수가 넣은 수와 같다.
- **비고**: 기존 명세: RT-G-4-02, RPC-018 / 자동 테스트: txpool-status / PR196 우선순위: P1/P2 / 기존 자동 테스트는 형식만 보므로 건수 대조로 바꾼다.

## CT-RPC-012 · 트랜잭션 풀 내용 조회

- **목적**: 대기·보류 항목에 보낸 이, nonce, 가스 가격이 들어 있는지 확인한다.
- **의존 요소**: 테스트 계정, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. CT-RPC-011과 같은 상태를 만든다.
    2. 풀 내용을 조회한다.
- **기대 결과**: 대기 항목에 연속 nonce, 보류 항목에 격차 nonce 트랜잭션이 상세 필드와 함께 있다.
- **비고**: 기존 명세: RT-G-4-03, RPC-018 / 자동 테스트: txpool-content-well-formed / PR196 우선순위: P1/P2

## CT-RPC-013 · 새 블록 구독

- **목적**: 웹소켓으로 새 블록 헤더를 실시간으로 받는지 확인한다.
- **의존 요소**: RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 웹소켓으로 새 블록 구독을 건다.
    2. 블록이 만들어질 때마다 헤더를 받는지 본다.
- **기대 결과**: 연속 헤더를 받고 번호가 늘어난다.
- **비고**: 기존 명세: RT-A-4-06, RPC-020 / 자동 테스트: ws-subscribe-new-heads / PR196 우선순위: P2 / 웹소켓 주소가 프로필에 있어야 한다.

## CT-RPC-014 · 이벤트 로그 구독

- **목적**: 웹소켓으로 특정 주소의 이벤트를 실시간으로 받는지 확인한다.
- **의존 요소**: 테스트 계정, 컨트랙트, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 이벤트 컨트랙트를 배포한다.
    2. 그 주소로 로그 구독을 건다.
    3. 이벤트를 내는 트랜잭션을 보낸다.
- **기대 결과**: 이벤트가 바로 수신된다.
- **비고**: 기존 명세: RT-A-4-07, RPC-021 / 자동 테스트: ws-subscribe-logs / PR196 우선순위: P2

## CT-RPC-015 · 노드 지표 조회

- **목적**: 노드가 내놓는 지표에서 최신 블록 높이를 읽을 수 있는지 확인한다.
- **의존 요소**: RPC 주소·API 노출, 노드 구성·시간
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 지표 기능을 켜고 노드를 띄운다.
    2. 최신 블록 높이 지표를 읽는다.
- **기대 결과**: 값이 1 이상이다.
- **체인별 차이**: 지표 기능을 켜는 옵션은 세 클라이언트가 같다.
- **비고**: 자동 테스트: stablenet-metric-head-block / 공개 RPC에는 지표 주소가 없을 수 있다.
