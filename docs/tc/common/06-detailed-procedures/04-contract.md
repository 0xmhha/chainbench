## CT-CONTRACT-001 · 컨트랙트 배포

- **목적**: 컨트랙트를 배포하면 주소가 생기고 코드가 조회되는지 확인한다.
- **의존 요소**: 테스트 계정, 컨트랙트
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 정해진 값을 돌려주는 작은 컨트랙트를 배포한다.
    2. 영수증의 컨트랙트 주소로 코드를 조회한다.
    3. 호출해 반환값을 확인한다.
- **기대 결과**: 코드가 비어 있지 않다. 반환값이 42다.
- **체인별 차이**: 배포할 코드가 세 체인의 EVM에서 모두 실행돼야 한다. WEMIX3.0은 최신 명령어(PUSH0)를 지원하지 않는다.
- **자동 테스트**: 2026-09-30에 체인별 파일 셋을 하나로 합쳤다. 배포 바이트코드와 기대값이 셋 다 같았고, wbft·wemix 사본은 stablenet 판과 preset·id만 달랐다. 사본 둘이 더 들고 있던 송금 두 단계는 옮기지 않았다. 그것은 CT-TX-001이 재는 것이고, 그 케이스가 2026-09-29부터 파일 하나로 세 체인을 돈다. 사본이 genesis에 얹던 node1 잔액도 옮기지 않았다. CT-CONTRACT-006이 세 체인에서 node1으로 배포하며 그 얹기 없이 돌고 있다. 사본에서 남긴 것은 앞에서 블록이 나오기를 기다리는 준비 단계다. 배포하는 런타임 10바이트는 0x2a를 메모리에 넣고 32바이트를 돌려준다.
- **비고**: 기존 명세: RT-A-3-01, TX-005 / 자동 테스트: contract-roundtrip / PR196 우선순위: P1/P2 / PR196에서는 네 가지 형식으로 각각 배포한다. / 2026-09-30에 wemix-tx-and-contract(PR196-TC-004), wbft-tx-and-contract(PR196-TC-027) 사본을 합쳐, 한 파일로 세 체인을 돈다.

## CT-CONTRACT-002 · 상태 변경 함수 호출

- **목적**: 저장값을 바꾸는 함수를 호출하면 바뀐 값이 조회되는지 확인한다.
- **의존 요소**: 테스트 계정, 컨트랙트
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 저장값 컨트랙트를 배포한다.
    2. 저장값을 바꾸는 트랜잭션을 보낸다.
    3. 조회 함수로 값을 읽는다.
- **기대 결과**: 상태가 성공이고 읽은 값이 바꾼 값이다.
- **체인별 차이**: CT-CONTRACT-001과 같다.
- **비고**: 기존 명세: RT-A-3-02, TX-005 / 자동 테스트: storage-write-and-read / PR196 우선순위: P1/P3 / 등록된 컨트랙트 호출 자동 테스트와 절차가 겹친다.

## CT-CONTRACT-003 · 조회 함수 호출

- **목적**: 트랜잭션 없이 조회 호출로 값을 읽을 수 있는지 확인한다.
- **의존 요소**: 컨트랙트
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 배포된 컨트랙트의 조회 함수를 호출한다.
- **기대 결과**: 정확한 값이 돌아오고 상태는 바뀌지 않는다.
- **체인별 차이**: CT-CONTRACT-001과 같다. 공통 테스트의 컨트랙트는 PUSH0 없이 손으로 쓴 바이트코드라 세 체인에서 배포된다.
- **자동 테스트**: CT-CONTRACT-002 의 저장 컨트랙트를 배포하고 0x2a 를 트랜잭션으로 써 둔다. 조회 호출로 0x2a 가 돌아오는지 본다. 그다음 쓰기 분기로 가는 데이터를 조회 호출로 보낸다. 조회 호출도 코드를 실행하지만 결과는 버려지므로, 뒤이어 읽은 저장소와 조회 값이 여전히 0x2a 이고 호출한 계정의 nonce 가 그대로인지 본다.
- **비고**: 기존 명세: RT-A-3-03, TX-005 / 공통 케이스(2026-09-29 신규): view-call-leaves-state / PR196 우선순위: P1/P2

## CT-CONTRACT-005 · 조회 호출의 되돌림 오류

- **목적**: 되돌리는 함수를 조회 호출하면 오류와 사유가 돌아오는지 확인한다.
- **의존 요소**: 컨트랙트
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 되돌리는 함수가 있는 컨트랙트를 배포한다.
    2. 그 함수를 조회 호출한다.
- **기대 결과**: 실행 되돌림 오류가 돌아온다.
- **체인별 차이**: 없다. 예전 자동 테스트의 컨트랙트 코드가 PUSH0 을 써서 WEMIX3.0 에서 배포가 실패했는데, PUSH0 없는 코드로 바꿨다.
- **자동 테스트**: 사유 없이 되돌리는 컨트랙트를 조회 호출해 `execution reverted` 오류가 돌아오는지 본다. 사유 문자열까지는 보지 않는다.
- **비고**: 기존 명세: RT-A-3-05 / 자동 테스트: eth-call-revert-returns-error / PR196 우선순위: P1/P2

## CT-CONTRACT-006 · 되돌림 트랜잭션의 실패 상태

- **목적**: 저장소를 쓴 뒤 되돌리는 거래가 채굴 실패하고 상태를 롤백하며 사용한 가스만 차감하는지 확인한다.
- **절차**:
    1. 0번 슬롯을 42로 초기화한 컨트랙트를 배포하고 런타임과 성공 영수증을 확인한다.
    2. 빈 calldata의 eth_call과 eth_getStorageAt으로 42를 확인한다.
    3. 새 호출자를 펀딩하고 잔액을 읽는다. calldata 0x01, gas 100000으로 SSTORE(1) 후 REVERT 분기를 실행한다.
    4. 실제 실패 영수증과 gasUsed < gasLimit, 정확한 gasUsed × effectiveGasPrice 차감을 확인한다.
    5. eth_call과 저장소가 42를 유지하고 체인이 계속 블록을 만드는지 확인한다.
- **자동 테스트**: 2026-09-30에 통합한 기존 배포 코드 확인·독립 호출자·잔액·블록 전진 단언을 보존했다.
  2026-10-14에는 저장소를 쓰지 않는 5바이트 REVERT fixture를 27바이트 상태 변경 fixture로 교체했다.
  Native 회귀가 실패 거래의 debug_traceTransaction에서 SSTORE 완료 뒤 실패를 확인하므로 쓰기 없는 fixture는 통과할 수 없다.
- **비고**: RT-A-3-06, TX-017. 세 체인 실제 실행과 RED→GREEN은 [실패·롤백 증거](../../../dev/transaction-failure-evidence.json)에 기록한다.

## CT-CONTRACT-007 · 가스 소진 트랜잭션

- **목적**: 저장소 쓰기 뒤 가스 소진으로 실패한 거래의 가스 전량 소비·상태 롤백·정확한 수수료를 확인한다.
- **절차**:
    1. 0번 슬롯을 42로 초기화한 26바이트 런타임을 배포하고 정확한 코드와 초기값을 확인한다.
    2. 새 호출자를 펀딩하고 잔액을 읽는다. calldata 0x01, gas 50000으로 SSTORE(1) 후 무한 반복 분기를 실행한다.
    3. 실제 실패 영수증, gasUsed == 50000, gasUsed × effectiveGasPrice 차감과 eth_call/저장소의 42 유지, 후속 블록 전진을 확인한다.
- **자동 테스트**: Native trace에서 실패 전에 실제 SSTORE가 완료돼야 한다. 준비 거절이나 쓰기 없는 루프는 롤백 증명이 아니다.
- **원문과의 차이**: RT-A-3-07의 가스 전량 소비와 롤백을 검증한다. TX-018 원문의 `estimateGas - 1` 절차를 이 무한 반복 fixture로 충족했다고 주장하지 않는다.
  WBFT 추정기는 상향 오차를 허용하므로 추정값에서 1을 뺀 한도가 항상 실패한다는 전제도 별도 검증이 필요하다.
  TX-018 전체는 열린 상태다. [범위와 증거](../../../dev/transaction-failure-evidence.json).
