## CT-FEE-001 · 최소 팁 미달 거부

- **목적**: 노드가 받는 최소 팁보다 낮은 팁으로 보내면 거부되는지 확인한다.
- **의존 요소**: 수수료 값
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 팁과 최대 수수료를 1로 정해 전송한다.
    2. 응답을 확인한다.
- **기대 결과**: 거부된다.
- **체인별 차이**: 최소 팁의 출처가 다르다. WEMIX3.0은 거버넌스가 노드에 넣어 주는 값, WEMIX4.0은 노드 실행 설정값, StableNet은 거버넌스 컨트랙트가 정한 팁이다(블록 헤더에도 같은 값이 기록된다).
- **비고**: 기존 명세: RT-A-2-05a, TX-002 / 자동 테스트: dynamic-fee-below-basefee-rejected / PR196 우선순위: P1

## CT-FEE-002 · 최소 가스비 경계값

- **목적**: 최소 가스비보다 낮으면 거부되고, 같거나 높으면 받아들여지는지 형식별로 확인한다.
- **의존 요소**: 수수료 값
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 체인의 최소 가스비를 조회하거나 설정에서 읽는다.
    2. 예전 형식, 접근 목록 형식, 동적 수수료 형식으로 각각 최소 미만·같음·초과 값을 보낸다.
    3. 응답과 영수증을 확인한다.
- **기대 결과**: 같음과 초과는 성공한다. 미만은 StableNet에서 거부된다. WEMIX3.0과 WEMIX4.0에서는 거부되거나 블록에 포함되지 않은 채 남는다.
- **체인별 차이**: 최소 가스비 검사 방식이 다르다. StableNet은 최대 수수료가 최소 기본 수수료와 최소 팁의 합보다 낮으면 풀에서 거부한다. WEMIX3.0과 WEMIX4.0의 풀은 팁 하한만 검사하고 최대 수수료 하한은 검사하지 않아, 최대 수수료가 기본 수수료보다 낮은 트랜잭션은 풀에 들어간 뒤 포함되지 않은 채 남는다. 두 체인은 판정을 미포함으로 두거나 팁 하한 경계로 바꿔야 한다.
- **비고**: 기존 명세: TC-1-3-01, TC-1-3-02, TC-1-3-03, TC-1-3-04, TC-1-3-05, TC-1-3-06, TS-1-3-01, TS-1-3-02 / 자동 테스트: legacy-gasprice-below-min-rejected, accesslist-gasprice-below-min-rejected, feecap-below-min-rejected, feecap-above-min-accepted, feecap-exact-min-accepted / PR196 우선순위: P1

## CT-FEE-003 · 사용률 높을 때 기본 수수료 증가

- **목적**: 블록 사용률이 기준을 넘으면 다음 블록 기본 수수료가 오르는지 확인한다.
- **의존 요소**: 수수료 값, 테스트 계정, 노드 직접 제어
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 기본 수수료를 기록한다.
    2. 기준을 넘는 사용률로 여러 블록 동안 부하를 준다.
    3. 기본 수수료를 다시 조회한다.
- **기대 결과**: 기본 수수료가 올랐다.
- **체인별 차이**: 기준과 변화폭이 다르다. StableNet은 20% 초과 시 2% 인상, WEMIX4.0은 표준 계산, WEMIX3.0은 거버넌스 값이다.
- **비고**: 기존 명세: RT-C-03 / 자동 테스트: anzeon-basefee-increase / PR196 우선순위: P1

## CT-FEE-004 · 사용률 보통일 때 기본 수수료 유지

- **목적**: 블록 사용률이 유지 구간이면 기본 수수료가 변하지 않는지 확인한다.
- **의존 요소**: 수수료 값, 테스트 계정, 노드 직접 제어
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 기본 수수료를 기록한다.
    2. 유지 구간의 사용률로 부하를 준다.
    3. 기본 수수료를 다시 조회한다.
- **기대 결과**: 기본 수수료가 같다.
- **체인별 차이**: 유지 구간이 다르다. StableNet은 6\~20%다. WEMIX4.0 표준 계산에는 유지 구간이 없어 목표 사용률에서만 유지된다.
- **비고**: 기존 명세: RT-C-04 / 자동 테스트: anzeon-basefee-stable / PR196 우선순위: P1

## CT-FEE-005 · 사용률 낮을 때 기본 수수료 감소

- **목적**: 부하가 끝나면 기본 수수료가 내려가는지 확인한다.
- **의존 요소**: 수수료 값, 테스트 계정, 노드 직접 제어
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 부하를 주어 기본 수수료를 올린다.
    2. 부하를 멈추고 여러 블록을 기다린다.
    3. 기본 수수료를 조회한다.
- **기대 결과**: 최고점보다 낮아졌다.
- **체인별 차이**: CT-FEE-003과 같다.
- **비고**: 기존 명세: RT-C-05 / 자동 테스트: anzeon-basefee-decrease / PR196 우선순위: P1

## CT-FEE-006 · 기본 수수료 하한

- **목적**: 기본 수수료가 체인이 정한 하한 아래로 내려가지 않는지 확인한다.
- **의존 요소**: 수수료 값
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 부하가 없는 상태에서 기본 수수료를 조회한다.
    2. 하한과 비교한다.
- **기대 결과**: 하한 이상이다.
- **체인별 차이**: 하한이 다르다. StableNet은 20,000 Gwei 상수, WEMIX3.0은 거버넌스 계산의 최솟값 1, WEMIX4.0은 0이다. 프로필 값과 비교한다.
- **비고**: 기존 명세: RT-C-06 / 자동 테스트: basefee-minimum / PR196 우선순위: P1 / 상한은 WEMIX4.0에 없어 부록(2체인)으로 뺐다.

## CT-FEE-007 · 실제 적용 가스 가격 기록

- **목적**: 영수증에 실제 적용 가스 가격이 기록되고 사용 가스가 기본값 이상인지 확인한다.
- **의존 요소**: 테스트 계정, 수수료 값
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 송금을 보낸다.
    2. 영수증의 실제 적용 가스 가격과 사용 가스를 조회한다.
- **기대 결과**: 가스 가격이 0보다 크고 사용 가스가 21000 이상이다.
- **비고**: 기존 명세: RT-A-2-08 / 자동 테스트: effective-gas-price / PR196 우선순위: P1

## CT-FEE-008 · 실제 적용 가스 가격 노드 간 일치

- **목적**: 같은 트랜잭션의 실제 적용 가스 가격이 생성 노드와 종단 노드에서 같은지 확인한다.
- **의존 요소**: 테스트 계정, 노드 구성·시간
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 생성 노드에 송금을 보내 영수증을 조회한다.
    2. 종단 노드가 그 블록까지 동기화되기를 기다린다.
    3. 종단 노드에서 같은 영수증을 조회해 비교한다.
- **기대 결과**: 두 노드의 값이 같다.
- **비고**: 기존 명세: TC-4-6-02 (부분 대응) / 자동 테스트: effective-gas-price-regular-bp-en / PR196 우선순위: P1 / 명세의 "헤더 팁으로 재계산" 부분은 StableNet 전용이라 제외하고 노드 간 일치만 가져왔다.

## CT-FEE-009 · 스냅 동기화 노드의 영수증 가스 가격 보존

- **목적**: 스냅 동기화로 받은 영수증에 이미 가스 가격이 있으면 덮어쓰지 않는지 확인한다.
- **의존 요소**: 노드 구성·시간
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 스냅 동기화 노드를 준비한다.
    2. 동기화 전에 만들어진 트랜잭션의 영수증을 두 노드에서 조회한다.
- **기대 결과**: 가스 가격이 생성 노드 값과 같다.
- **비고**: 기존 명세: TC-4-6-03, TS-4-6 / TS-4-6의 인증 계정 부분은 StableNet 전용.

## CT-FEE-010 · 권장 가스 가격 조회

- **목적**: 권장 가스 가격이 기본 수수료와 팁의 합으로 나오는지 확인한다.
- **의존 요소**: 수수료 값, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 권장 가스 가격을 조회한다.
    2. 최신 블록의 기본 수수료와 체인의 팁 출처 값을 조회한다.
    3. 합과 비교한다.
- **기대 결과**: 권장 가격이 기본 수수료와 팁의 합이고 0보다 크다.
- **체인별 차이**: 계산식은 세 클라이언트가 같고 팁 출처만 다르다. StableNet은 블록 헤더의 팁, WEMIX3.0은 거버넌스 제안값, WEMIX4.0은 하드포크 전에는 고정값이고 하드포크 후에는 최근 블록 표본이다.
- **비고**: 기존 명세: RT-G-2-01, RPC-016 / 자동 테스트: gas-price-positive, gas-price-equals-basefee-plus-tip / PR196 우선순위: P2

## CT-FEE-012 · 수수료 이력 조회

- **목적**: 최근 블록의 기본 수수료 이력이 형식에 맞게 나오는지 확인한다.
- **의존 요소**: RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 최근 16개 블록의 수수료 이력을 조회한다.
    2. 시작 블록과 기본 수수료 배열을 확인한다.
- **기대 결과**: 시작 블록이 16진수이고 기본 수수료 배열이 있다.
- **체인별 차이**: StableNet 명세의 "하한 이상" 조건은 StableNet 전용이다.
- **비고**: 기존 명세: RT-G-2-03, RPC-017 / 자동 테스트: fee-history-well-formed / PR196 우선순위: P2
