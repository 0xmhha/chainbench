## CT-FEE-001 · 최소 팁 미달 거부

- **목적**: 노드가 받는 최소 팁보다 낮은 팁으로 보내면 거부되는지 확인한다.
- **의존 요소**: 수수료 값
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 노드를 트랜잭션 풀 로컬 처리 없이(`txpool.nolocals`) 띄운다.
    2. 최대 수수료는 기본 수수료와 팁을 충분히 넘게, 팁만 1로 정해 전송한다.
    3. 응답을 확인한다.
- **기대 결과**: 거부된다(`transaction underpriced`). 블록은 계속 만들어진다.
- **체인별 차이**: 최소 팁의 출처가 다르다. WEMIX3.0은 거버넌스가 노드에 넣어 주는 값, WEMIX4.0은 노드 실행 설정값, StableNet은 거버넌스 컨트랙트가 정한 팁이다(블록 헤더에도 같은 값이 기록된다). 2026-09-30 측정에서 StableNet 27600 Gwei, WEMIX4.0 100 Gwei 였다. 거부 문구는 StableNet·WEMIX4.0 이 `transaction underpriced: gas tip cap …`, WEMIX3.0 이 `transaction underpriced` 다.
- **자동 테스트**: 최대 수수료를 1로 두면 팁 검사 전에 최대 수수료 검사에서 거부되어 팁 하한을 보지 못한다(CT-FEE-002 와 같은 것을 본다). 또 RPC 로 제출한 트랜잭션은 로컬로 취급되어 StableNet·WEMIX4.0 이 최소 팁 검사를 면제한다(`core/txpool/legacypool/legacypool.go` 의 local 분기) — 최대 수수료가 충분하면 팁 0 도 블록에 들어갔다. 그래서 `txpool.nolocals` 로 띄우고, 최대 수수료를 "최신 기본 수수료 × 2 + `eth_maxPriorityFeePerGas`" 로, 팁을 1 wei 로 보낸다. 정확한 경계(최소 팁 − 1)는 최소 팁을 세 체인에서 같은 방법으로 읽을 수 없어 보지 않는다.
- **비고**: 기존 명세: RT-A-2-05a, TX-002 / 자동 테스트: tip-below-min-rejected / PR196 우선순위: P1

## CT-FEE-002 · 최소 가스비 경계값

- **목적**: 최소 가스비보다 낮으면 거부되고, 같거나 높으면 받아들여지는지 형식별로 확인한다.
- **의존 요소**: 수수료 값
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 체인의 최소 가스비를 조회하거나 설정에서 읽는다.
    2. 예전 형식, 접근 목록 형식, 동적 수수료 형식으로 각각 최소 미만과 초과 값을 보낸다.
    3. 응답과 영수증을 확인한다.
- **기대 결과**: 초과는 성공한다. 미만은 StableNet에서 거부된다. WEMIX3.0과 WEMIX4.0에서는 거부되거나 블록에 포함되지 않은 채 남는다.
- **체인별 차이**: RPC 로 보낸 트랜잭션의 하한이 체인마다 다르다. StableNet 은 최대 수수료가 최소 기본 수수료(고정 상수)보다 낮으면 풀에서 거부한다. WEMIX3.0 은 최대 수수료가 "다음 블록 기본 수수료 + 거버넌스 팁" 보다 낮거나 팁이 거버넌스 팁보다 낮으면 거부한다. WEMIX4.0 은 RPC 로 받은 트랜잭션을 제출 때 가격으로 거부하지 않고, 최대 수수료가 포함 블록의 기본 수수료보다 낮으면 블록에 넣지 않는다. 그래서 "최소 가스비와 같은 값" 은 세 체인에 같은 값이 없어 공통에서 뺐다(부록 B).
- **자동 테스트**: 미만은 가스 가격 또는 최대 수수료를 1 wei 로 보내 거부(WEMIX4.0 은 미포함)를 본다. 초과는 새 계정이 자기 키로 예전 형식과 접근 목록 형식은 `eth_gasPrice` 로, 동적 수수료 형식은 "최신 기본 수수료 × 2 + `eth_maxPriorityFeePerGas`" 로 보내 성공 상태와 형식을 본다.
- **비고**: 기존 명세: TC-1-3-01, TC-1-3-02, TC-1-3-03, TC-1-3-04, TC-1-3-05, TC-1-3-06, TS-1-3-01, TS-1-3-02 / 자동 테스트: legacy-gasprice-below-min-rejected, accesslist-gasprice-below-min-rejected, feecap-below-min-rejected, feecap-above-min-accepted (StableNet 전용), feecap-exact-min-accepted (StableNet 전용) / 공통 케이스(2026-09-29 신규): legacy-gasprice-above-min-accepted, accesslist-gasprice-above-min-accepted, dynamic-feecap-above-min-accepted / PR196 우선순위: P1

## CT-FEE-007 · 실제 적용 가스 가격 기록

- **목적**: 영수증에 실제 적용 가스 가격이 기록되고 사용 가스가 기본값 이상인지 확인한다.
- **의존 요소**: 테스트 계정, 수수료 값
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 송금을 보낸다.
    2. 영수증의 실제 적용 가스 가격과 사용 가스를 조회한다.
- **기대 결과**: 가스 가격이 0보다 크고 사용 가스가 21000 이상이다.
- **비고**: 기존 명세: RT-A-2-08 / 자동 테스트: effective-gas-price / PR196 우선순위: P1

## CT-FEE-008 · 실제 적용 가스 가격 노드 간 일치

- **목적**: 같은 트랜잭션의 실제 적용 가스 가격이 생성 노드와 종단 노드에서 같은지 확인한다.
- **의존 요소**: 테스트 계정, 노드 구성·시간
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 생성 노드에 송금을 보내 영수증을 조회한다.
    2. 종단 노드가 그 블록까지 동기화되기를 기다린다.
    3. 종단 노드에서 같은 영수증을 조회해 비교한다.
- **기대 결과**: 두 노드의 값이 같다.
- **비고**: 기존 명세: TC-4-6-02 (부분 대응) / 자동 테스트: effective-gas-price-regular-bp-en / PR196 우선순위: P1 / 명세의 "헤더 팁으로 재계산" 부분은 StableNet 전용이라 제외하고 노드 간 일치만 가져왔다.

## CT-FEE-009 · 스냅 동기화 노드의 영수증 가스 가격 보존

- **목적**: 스냅 동기화로 받은 영수증의 실제 적용 가스 가격이 생성 노드와 같은지 확인한다.
- **의존 요소**: 노드 구성·시간, 노드 직접 제어
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 스냅 동기화 노드를 준비한다.
    2. 동기화 전에 만들어진 트랜잭션의 영수증을 두 노드에서 조회한다.
- **기대 결과**: 가스 가격, 사용 가스, 상태가 생성 노드 값과 같다.
- **체인별 차이**: 네트워크로 받은 영수증에는 가스 가격이 없어 받는 노드가 다시 구한다. StableNet 은 헤더 팁과 인증 계정 여부로, WEMIX4.0 은 트랜잭션과 기본 수수료로, WEMIX3.0 은 조회 API 에서 계산한다. 방법은 달라도 결과는 생성 노드와 같아야 한다. "이미 값이 있으면 덮어쓰지 않는다" 와 인증 계정 부분은 StableNet 내부 동작이라 공통에서는 결과만 비교한다.
- **자동 테스트**: CT-NODE-005 와 같은 방법으로 스냅 노드를 만든다(genesis 상태로 되돌린 종단 노드를 블록이 150개 쌓인 뒤 띄우고, 지표 `eth_downloader_receipts_in` 으로 snap 을 탔는지 확인). 새 계정의 동적 수수료 송금을 그 전에 보내 두고, 영수증의 effectiveGasPrice, gasUsed, status 를 두 노드에서 비교한다.
- **비고**: 기존 명세: TC-4-6-03, TS-4-6 / 공통 케이스(2026-09-29 신규): snap-receipt-gas-price / TS-4-6의 인증 계정 부분은 StableNet 전용.

## CT-FEE-010 · 권장 가스 가격 조회

- **목적**: 권장 가스 가격이 기본 수수료와 팁의 합으로 나오는지 확인한다.
- **의존 요소**: 수수료 값, RPC 주소·API 노출
- **분리 방식**: 설정으로 분리, 기대값은 체인별 계산
- **절차**:
    1. 권장 가스 가격을 조회한다.
    2. 최신 블록의 기본 수수료와 체인의 팁 출처 값을 조회한다.
    3. 합과 비교한다.
- **기대 결과**: 권장 가격이 기본 수수료와 팁의 합이고 0보다 크다.
- **체인별 차이**: 계산식은 세 클라이언트가 같고 팁 출처만 다르다. StableNet은 블록 헤더의 팁, WEMIX3.0은 거버넌스 제안값, WEMIX4.0은 하드포크 전에는 고정값이고 하드포크 후에는 최근 블록 표본이다.
- **자동 테스트**: gas-price-positive 는 팁을 `eth_maxPriorityFeePerGas` 로 읽어, 권장 가격이 같은 head 의 기본 수수료와 그 팁의 합인지 본다. 세 체인에서 그대로 돈다.
- **비고**: 기존 명세: RT-G-2-01, RPC-016 / 자동 테스트: gas-price-positive, gas-price-equals-basefee-plus-tip (StableNet 전용) / PR196 우선순위: P2

## CT-FEE-012 · 수수료 이력 조회

- **목적**: 최근 블록의 기본 수수료 이력이 형식에 맞게 나오는지 확인한다.
- **의존 요소**: RPC 주소·API 노출
- **분리 방식**: 설정으로 분리
- **절차**:
    1. 최근 16개 블록의 수수료 이력을 조회한다.
    2. 시작 블록과 기본 수수료 배열을 확인한다.
- **기대 결과**: 시작 블록이 16진수이고 기본 수수료 배열이 있다.
- **체인별 차이**: StableNet 명세의 "하한 이상" 조건은 StableNet 전용이다.
- **비고**: 기존 명세: RT-G-2-03, RPC-017 / 자동 테스트: fee-history-well-formed / PR196 우선순위: P2
